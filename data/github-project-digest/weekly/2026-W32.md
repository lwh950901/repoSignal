## 1. pdf-inspector

- 仓库：[firecrawl/pdf-inspector](https://github.com/firecrawl/pdf-inspector)
- 项目简介：面向需要处理 PDF 的开发者，提供纯 Rust 的 PDF 分类、文本抽取和 Markdown 转换库，并交付 Python、Node.js、WASM 绑定与 CLI。它适合在 RAG、文档处理和 OCR 分流链路中本地运行。
- 入选理由：日报记录其当日 Trending 增长约 1,769 Stars；实时仓库页显示约 13.0k Stars、887 Forks、46 个 Issue 和 54 个 PR，README 还提供 200 份 PDF 的可复现实验与多语言入口。它的选择依据不只是增长，而是基准、架构和安全修复同时成立。
- 质量与维护：实时仓库页显示 429 次提交、`src`/`tests`/`docs`/`examples`/绑定层分层清楚；日报记录 2026-08-03 升级 `lopdf` 并修复嵌套 PDF 拒绝服务风险。实时 Releases 页显示暂无正式 Release，这是发布成熟度的扣分项。
- 主要技术栈：Rust、lopdf、PyO3、N-API、WebAssembly、Python、Node.js。
- 实时指标：实时仓库页约 13.0k Stars / 887 Forks；MIT；未归档。日报当日记录为 7,952 Stars / 532 Forks，存在明显时间差；实时 Releases 页暂无正式 Release。
- 真实风险：不执行 OCR，扫描件仍需外部分流；项目方基准语料有限，复杂字体、恶意 PDF 和超大文件需要在隔离环境中用自有数据复测。没有正式 Release 时，生产依赖应锁定提交或包版本并建立回归集。
- 上手建议：先用本地真实 PDF 跑分类结果和 Markdown 输出，再单独测试表格、多栏、混合型和恶意输入；确认扫描页路由后再接入 OCR，不要直接把 README 基准当作自身数据保证。
- 本周精选价值：这是本周最完整的文档解析基础设施候选之一，把低层解析、多语言分发、可复现实验和安全响应连成了可使用、可学习的工程样本。

## 4. code-review-graph

- 项目简介：面向大型代码库和 AI 编程工具，构建持久化代码关系图，并通过 MCP、CLI 和 GitHub Action 返回按变更影响裁剪的审查上下文。它以本地优先的 Python 工具交付。
- 入选理由：实时仓库页显示约 2.7k Forks、51 个 Issue、27 个 PR 和 911 次提交；v2.3.7 Release 明确记录 15/15 与 13/13 检查通过，并关闭三个高严重度 CodeQL 告警。结构化图分析、可复现评测和多宿主接入共同证明它解决的是 Agent 读大型仓库的真实瓶颈。
- 质量与维护：README 提供 Tree-sitter 解析、blast-radius、增量更新、安装/卸载边界和多语言文档；仓库包含 tests、CI、SECURITY.md 与评测目录。实时 Release v2.3.7（2026-07-18）含多语言覆盖、MCP 并发和安全处理改进。
- 主要技术栈：Python、Tree-sitter、SQLite/FTS5、MCP、sentence-transformers/兼容 Embeddings、D3.js、GitHub Actions。
- 实时指标：日报核验记录 28,974 Stars / 2,681 Forks；实时页面约 2.7k Forks、51 个 Issue；MIT；未归档；最新可见 Release v2.3.7。
- 真实风险：上下文缩减和 recall 基准仍有项目方评测边界，README 的中位数不能当作保证；小文件变更可能不值得建图，远程 Embedding 端点还会带来代码数据边界风险。
- 上手建议：先在一个中型仓库比较直接读取与图裁剪的审查结果，核对遗漏的调用者、测试和生成代码；默认使用本地存储/模型，接远程 Embedding 前先审查数据驻留和脱敏策略。
- 本周精选价值：它把 Agent 代码审查从“多读一些文件”推进到可解释的结构图、影响分析、评测和工具集成，是本周最有二次开发价值的代码智能项目之一。

## 5. rtk

- 仓库：[rtk-ai/rtk](https://github.com/rtk-ai/rtk)
- 项目简介：面向使用 Claude Code、Codex、Gemini CLI、Cursor 等 Agent 工具的开发者，在命令输出进入模型上下文前完成过滤、分组、截断和去重。它以 Rust 单二进制、Shell hooks、Homebrew 与 Cargo 包交付。
- 入选理由：8 月 8 日补录日报将其评为 91/100；项目覆盖 100 多个常见命令，并把上下文压缩放在 Agent Bash 调用与原始工具输出之间。目标明确、接入成本低，也便于在真实仓库做 A/B 对照。
- 质量与维护：日报记录 GitHub Release 页列出 v0.45.0，2026-08-06 提交包含 Copilot hook 自愈修复；README 提供逐类命令压缩策略、架构说明、安全检查 CI、安装包以及 Windows/WSL 和多宿主初始化路径。
- 主要技术栈：Rust、Shell hooks、Homebrew、Cargo、GitHub Actions、CLI。
- 实时指标：8 月 9 日补录日报记录 75,248 Stars / 4,735 Forks；Apache-2.0；未归档；最近推送为 2026-08-07 13:41 UTC；Release 页列出 v0.45.0。
- 真实风险：项目方“最多减少 90% Bash 输出”不等于账单减少 90%，绝对 token 数也只是 bytes/4 估算；自动 hook 可能改变输出语义，故障排查仍需保留原始命令，并核对 README 与 Release 的版本差异。
- 上手建议：先在一个小仓库只接管 `git status`、`git diff` 和测试命令，对比压缩前后遗漏信息、上下文体积与排障体验；确认可逆后再扩大命令覆盖。
- 本周精选价值：它把上下文工程落到一条可直接测量的命令链路，既能当天试用，也能帮助团队判断“减少输出”是否真正改善 Agent 质量。

- 质量与维护：README 提供稳定 JSON 合约、退出码和只阻断新增问题的 `fallow audit`；仓库含 tests、fuzz、benchmarks、SECURITY.md、Docker 示例。最新 Release 记录 mock-aware coverage、workspace discovery 和 alias propagation 改进。
- 主要技术栈：Rust、TypeScript/JavaScript/CSS 分析器、npm/pnpm/yarn、MCP、GitHub Actions、JSON/SARIF/Code Climate。
