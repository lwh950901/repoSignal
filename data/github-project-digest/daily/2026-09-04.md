## 主推荐

### 1. 爆发型：google-research/timesfm — 93/100

- 仓库：[google-research/timesfm](https://github.com/google-research/timesfm)
- 一句话定位：Google Research 开源的时间序列基础模型，用于零样本、多变量和带协变量的预测。
- 类型与适合用途：爆发型；适合想快速试用时间序列 Foundation Model、做需求/库存/容量预测，或研究预训练模型如何适配结构化序列的开发者。
- 核心亮点与场景：TimesFM 3.0 新增原生多变量预测、过去/未来协变量和分位数输出；可从 PyPI 或本地安装，用 NumPy 数组直接生成预测，适合将预测能力接入数据管线或 Agent 工具。
- 主要技术栈：Python、PyTorch、NumPy、Hugging Face、PEFT/LoRA、时间序列基准评测。
- 实时指标：GitHub Trending 2026-09-04 显示约新增 1,626 Stars；当前约 30,643 Stars / 2,923 Forks；Apache-2.0 源码，公开且未归档，仓库约 361 commits、149 Issues、88 Pull requests。
- 近期有意义活动：Trending 页面在 2026-09-04 记录热度；提交页可核验 2026-09-02 的 covariate window 对齐、placeholder shape 和测试修复，2026-08-27 至 09-01 集中加入 TimesFM 3.0 evaluator、benchmark suite 与 README/许可证说明；README 标注 2026 年 8 月 TimesFM 3.0 更新。
- 质量证据：1) `tests/`、`.github/workflows`、`timesfm-forecasting/` 与 `timesfm3-usage/` 提供测试、CI、教程和可复现实验入口；2) README 给出 PyPI/uv 安装和单变量、多变量协变量代码；3) README 明确列出 fev-bench、TIME、GIFT-Eval 的评测结果与模型版本差异。
- 风险：源码和 2.5 及以前权重为 Apache-2.0，但 TimesFM 3.0 预训练权重目前使用单独的非商业许可证，限制商业和生产使用；README 也明确开源版本不是官方支持的 Google 产品，生产接入前必须单独核对权重许可、算力和预测误差。
- 推荐理由：它同时有当前实时热度、日期明确的 3.0 架构升级和可运行示例；推荐的不是“星多”，而是它把新模型能力、benchmark、测试和实际调用入口放在同一个可核验仓库里。

### 2. 实用型：langchain-ai/langgraph — 92/100

- 仓库：[langchain-ai/langgraph](https://github.com/langchain-ai/langgraph)
- 一句话定位：面向长时运行、有状态 Agent 的低层编排框架，提供持久化、恢复和人工介入能力。
- 类型与适合用途：实用型；适合需要把 Agent 工作流做成可恢复、可观测、可插入人工审批的 Python/TypeScript 服务团队。
- 核心亮点与场景：把 durable execution、human-in-the-loop、短期/长期 memory、subgraph 和 checkpoint 作为基础设施，适合客服升级、研究流程、代码审查和多步骤业务自动化，而不是只写一次性链式 Demo。
- 主要技术栈：Python、TypeScript/JavaScript、LangChain 生态、checkpoint backend、LangSmith tracing、pytest/CI。
- 实时指标：当前约 41,002 Stars / 6,918 Forks；MIT；公开且未归档，仓库约 7,069 commits、500 Issues、243 Pull requests；扫描器实时 Search 的 `pushed_at` 为 2026-09-03T15:23:28Z。
- 近期有意义活动：Release 页可核验 `langgraph==1.2.11` 于 2026-08-11 发布，并包含 `trace_policy`、checkpoint conformance suite 和依赖维护；仓库页有 `docs/`、`examples/`、`libs/` 与 Actions，近期持续提交。
- 质量证据：1) README 提供 `pip install -U langgraph`、Quickstart、API reference、Guides 和免费 LangGraph Academy；2) `docs/`、`examples/`、`libs/`、Makefile、Actions、LICENSE、CONTRIBUTING 和 SECURITY 形成完整工程入口；3) Release notes 同时覆盖 SDK、checkpoint、测试和依赖升级，符合实用型至少三项生产就绪信号。
- 风险：低层抽象自由度高，意味着状态 schema、checkpoint backend、幂等性和人工介入语义需要自行设计；LangSmith 等配套服务可能带来额外成本与数据边界，不能把“production-ready”文案当成自身合规或可靠性结论。
- 推荐理由：安装与 Quickstart 直接可用，文档、示例、测试/CI、稳定 Release 和近期维护齐全；先做一个带 checkpoint 和人工审批的最小图，再评估是否需要上层 Deep Agents。

- 核心亮点与场景：它把 hardware profiling、模型推荐、下载、服务健康检查和 Agent 接线放在一个运行时；可连接 Pi、OpenCode、Hermes、OpenClaw、Codex、Claude Code 和 Cline，也能使用内置 harness，适合做隐私优先的本地 Agent 原型。

- 核心亮点与场景：同一仓库覆盖 Python 风格格式 API、C++20 `std::format`/C++23 `std::print` 对接、Unicode、用户自定义类型和安全 printf；适合从 `include/fmt`、`src`、`test`、`CMakeLists.txt` 逐层阅读，并用 Compiler Explorer 或本地测试复现。
- 主要技术栈：C++、CMake、模板元编程、IEEE 754/Dragonbox、GitHub Actions、单元测试、模糊测试与独立 benchmark。
- 实时指标：GitHub Trending 2026-09-04 记录约新增 955 Stars；当前约 24,967 Stars / 3,010 Forks；MIT；公开且未归档，仓库约 7,963 commits、5 Issues、6 Pull requests。

- 风险：README 的速度表依赖特定编译器、平台、输入和优化参数，不能直接外推到业务系统；C++ 模板、ABI、locale 和编译期/运行期边界也不宜照搬，学习时应先复现测试与 benchmark，再评估真实 workload。
- 推荐理由：它不是今天最贴近 Agent 的项目，却是一个极高密度的工程学习对象；用小而完整的代码库理解 API、性能、可移植性和测试之间的取舍，能反哺本地推理与 Agent runtime 设计。
