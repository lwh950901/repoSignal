- 主要技术栈：TypeScript、PostgreSQL、容器化沙箱、Web UI。
- 实时指标：11,082 Stars / 1,199 Forks；MIT；未归档、非 Fork（2026-08-05 同轮 GitHub Search API）。
- 近期有意义活动：2026-08-04 连续合并 app shell，增加 portal origin 精确测试与贡献指南；v0.1.4 于 2026-07-31 发布。

- 风险：仓库极新，11k Stars 的爆发速度尚未转化为长期运维证据；组织权限、密钥与持久沙箱组合扩大了配置错误和供应链风险，生产部署前必须复核威胁模型。
- 推荐理由：增长、工程结构和风险披露同时成立，不只是一个聊天 UI；其 scope 隔离与共享治理正好回应团队 Agent 从个人工具走向真实工作系统的难点。

### 4. 学习型：sqliteai/waste — 89/100

- 仓库：[sqliteai/waste](https://github.com/sqliteai/waste)
- 一句话定位：用 NVMe 流式读取激活专家权重、在有限内存上运行 Kimi K3 的零运行时依赖 C 推理引擎。
- 类型与适合用途：学习型系统软件与实验性推理引擎；适合拆解 MoE 权重流式调度、受限缓存、量化容器与差分验证。
- 核心亮点与场景：将模型 trunk 常驻内存、按需从磁盘读取专家并以剩余 RAM 作为有界缓存，公开记录内存预算、SSD 吞吐、page fault 反直觉退化和多模态路径。
- 主要技术栈：C、CMake、NVMe I/O、量化、MoE/线性注意力、HTTP/CLI。
- 实时指标：1,663 Stars / 130 Forks；Apache-2.0；未归档、非 Fork（2026-08-05 同轮 GitHub Search API）。
- 近期有意义活动：v0.6.5 于 2026-08-04 发布；同日增加 checkpoint 级 `--reclaim` 证明、转换磁盘回收与 Open WebUI 文档。
- 质量证据：值得拆解的实现包括权重感知流式引擎、有界专家缓存和模型容器；GATES/SERVE 文档描述层输出、最终 logits、转换 round-trip、视觉 oracle 与 prompt renderer 差分测试；LEARNED/RESEARCH 专门保留失败优化和开放问题，体现很新的实验工程方法。
- 风险：不宜直接照搬到生产：API/格式未冻结、代码由 LLM 大量生成、项目明确承认快速变化与不稳定；K3 实测依赖约 64 GB 内存和高吞吐内部 NVMe，自报性能也需在目标硬件独立复现。
- 推荐理由：这是今天最完整的学习样本，价值不在“直接部署”，而在把缓存命中率、内存压力、磁盘带宽和正确性门禁放进同一套可读实现与实验记录中。

- 仓库：[trycompai/crm](https://github.com/trycompai/crm)
- 一句话定位：以 Agent 为一等成员、强调证据与数据边界的开源 CRM。
- 类型与适合用途：全栈业务应用与 Agent 工作区；适合研究销售/客户运营中的受控 Agent、证据简报和人机协作数据模型。
- 核心亮点与场景：工具、Skill、Schedule 都以文件形式版本化；生产沙箱默认 deny-all egress 且不注入数据库凭据，通过显式工具面访问业务数据。
- 主要技术栈：TypeScript、Bun、PostgreSQL、Vercel Sandbox/Docker/microsandbox、Agent runtime。
- 实时指标：4,546 Stars / 484 Forks；MIT；未归档、非 Fork（2026-08-05 同轮 GitHub Search API）。
- 近期有意义活动：2026-08-04 更新测试依赖与 workspace 行为文档，并连续合并 landing/agent 界面改进；仓库 Release feed 同日仍在更新，但未核实到稳定版本号。
- 质量证据：README 给出应用/Agent 分层目录与三条代码约束；SECURITY.md 单独说明授权模型；本地 Quick Start 使用 Bun 与 Docker Compose，且明确测试命令和生产沙箱差异。
- 风险：项目创建不足一周，社区与迁移兼容性尚未经过时间验证；CRM 中的客户数据敏感，即使沙箱无网络/无 DATABASE_URL，也必须继续审计工具授权、身份匹配和日志泄漏。
- 推荐理由：它不是给现有 CRM 简单加聊天框，而是从数据边界、证据和文件化技能重新设计 Agent 工作面；可运行性和安全说明使其达到正式推荐门槛，但成熟度限制了得分。
