## 主推荐

### 1. 爆发型：volcengine/OpenViking — 87/100

- 仓库：[volcengine/OpenViking](https://github.com/volcengine/OpenViking)
- 一句话定位：面向 AI Agent 的文件系统式上下文数据库，统一管理记忆、资源与技能。
- 类型与适合用途：Agent/RAG 基础设施；适合需要本地或自托管长期记忆、分层上下文交付和多 Agent 上下文隔离的团队。
- 核心亮点与场景：用 `viking://` 层级组织资源、会话和记忆，并提供 CLI、服务端与 OpenClaw/Claude Code 等集成；适合构建可持续积累知识的编码或工作 Agent。
- 主要技术栈：Python、Rust、Docker、向量检索、Agent 插件。
- 实时指标：26,229 Stars / 2,036 Forks；主项目 AGPL-3.0（CLI 与 examples 为 Apache-2.0）；公开、未归档、非 fork。指标由 GitHub API 于 2026-07-02 08:30（Asia/Shanghai）前后实时获取。
- 近期有意义活动：GitHub API 显示 2026-07-01 仍有 push；仓库提交页可核验近期持续进行存储树优化、向量后端持久化和 VikingDB 批处理修复；Release 页显示 v0.3.x 连续交付记忆、插件与安全改进。
- 质量证据：仓库包含多语言文档、测试、CI、SECURITY.md 与 Docker 部署材料；Release notes 记录了跨 30–40+ 变更的功能、兼容性和安全修复；Issue/PR 活跃且问题描述具体，可观察真实生产反馈。
- 风险：主项目 AGPL-3.0 对闭源网络服务有合规约束；开放问题多，Windows、多租户和存储迁移仍有边界问题，接入生产前应做数据隔离与升级演练。
- 推荐理由：增长信号强且不是概念 Demo；它把 Agent 上下文从零散向量库提升为可管理的资源、记忆和技能层，工程价值明确。

### 2. 实用型：alibaba/zvec — 91/100

- 仓库：[alibaba/zvec](https://github.com/alibaba/zvec)
- 一句话定位：可直接嵌入应用进程、同时支持向量与全文混合检索的轻量数据库。
- 类型与适合用途：嵌入式向量数据库/检索基础设施；适合本地 RAG、桌面应用、边缘设备和不希望运维独立向量服务的后端。
- 核心亮点与场景：单进程内提供 dense/sparse vector、全文检索、结构化过滤、WAL 和 DiskANN；适合把检索能力直接打包进 Python、Node.js、Go、Rust 或 Flutter 产品。
- 主要技术栈：C++、Python、SWIG、CMake、RocksDB/DiskANN，另有 Node.js、Go、Rust 与 Dart SDK。
- 实时指标：12,679 Stars / 754 Forks；Apache-2.0；公开、未归档、非 fork。指标由 GitHub API 于 2026-07-02 08:30（Asia/Shanghai）前后实时获取。
- 近期有意义活动：GitHub API 显示 2026-07-01 仍有 push；v0.5.1 于 2026-06-24 发布；近期提交修复 Python wheel、索引删除后的 RocksDB 清理，并加入外部向量源与 mmap 配置。
- 质量证据：289 次提交并具备 tests、CI、代码覆盖率、贡献指南和跨平台构建；README 提供一分钟示例、平台矩阵及可追溯 benchmark 文档；v0.5 系列交付全文检索、混合检索、DiskANN 和多语言 SDK。
- 风险：仍处于 0.x 版本，API 与存储格式可能变化；写入为单进程独占，且官方性能结论应在自己的数据规模和过滤模式下复测。
- 推荐理由：相比部署独立向量服务，它以更低运维成本提供完整混合检索能力，成熟度、文档和工程活动均高于同类新项目。

### 3. 潜力型：perplexityai/bumblebee — 82/100

- 仓库：[perplexityai/bumblebee](https://github.com/perplexityai/bumblebee)
- 一句话定位：只读扫描本机开发工具与包元数据，检查已知软件供应链攻击暴露面的安全工具。
- 类型与适合用途：开发者安全/供应链检查器；适合个人工作站、CI 前置检查和企业开发环境盘点。
- 核心亮点与场景：扫描包管理器、编辑器扩展、MCP 服务和 Agent skill 锁文件，并用离线威胁目录匹配暴露版本；只读设计降低了检查工具自身的操作风险。
- 主要技术栈：Go、GitHub Actions、GoReleaser、OSV 数据与离线威胁目录。
- 实时指标：4,688 Stars / 421 Forks；Apache-2.0；公开、未归档、非 fork。指标由 GitHub API 于 2026-07-02 08:30（Asia/Shanghai）前后实时获取。
- 近期有意义活动：GitHub API 显示 2026-06-25 有 push；Release 页可核验最新 v0.1.2；近期提交新增 GlassWorm 暴露目录、Agent skill 扫描、离线 OSV 目录生成器和 MCP server 盘点。
- 质量证据：仓库包含 SECURITY.md、贡献指南、CI 和 GoReleaser 配置；威胁目录带独立文档和 PR 审核流程；功能边界明确为只读盘点与已知暴露匹配，没有夸大为通用杀毒软件。
- 风险：仅 14 次主分支提交且为 v0.1.x，维护历史短；检测能力取决于威胁目录的及时性与覆盖面，阴性结果不能证明环境安全。
- 推荐理由：它覆盖了 Agent/MCP 生态快速扩张后容易忽略的本地供应链盲区，体量小、可审计，适合作为现有 SCA/EDR 的补充而非替代。
