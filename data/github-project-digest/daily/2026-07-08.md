## 主推荐

### 1. 爆发型：antirez/ds4 — 83/100

- 仓库：[antirez/ds4](https://github.com/antirez/ds4)
- 一句话定位：面向 DeepSeek V4 Flash/PRO 的自包含本地推理引擎，集成 Metal、CUDA、ROCm、HTTP API 与编码 Agent。
- 类型与适合用途：本地 AI 基础设施；适合拥有 96GB 以上统一内存或高端 GPU、希望验证大模型本地推理和 Agent 工作负载的工程师。
- 核心亮点与场景：围绕单一模型做端到端优化，包含 KV 状态、SSD streaming、工具调用、服务端与质量/速度测试，可用于本地编码 Agent 和推理内核研究。
- 主要技术栈：C、CUDA、Metal、ROCm、GGUF。
- 实时指标：17,877 Stars / 1,535 Forks；MIT；未归档（2026-07-08 GitHub Search API 实时值）。
- 近期有意义活动：GitHub API 显示 2026-07-03 有推送；提交页可核验近期服务端 JSON 解析加固、ROCm 启动修复、Metal tensor 释放保护及 SSD streaming 工作；尚无正式 GitHub Release。
- 质量证据：仓库包含 332 次提交、测试向量、发布前 QA 清单和独立 benchmark 工具；README 明确给出不同硬件/量化配置的实测数据；项目公开说明 beta 状态、硬件下限和模型兼容边界。
- 风险：项目仅成立数月且明确为 beta，内置 Agent 仍为 alpha；硬件门槛高，并可能随模型生态变化移除旧模型支持；部分性能数据主要来自项目自身。
- 推荐理由：增长信号很强，但真正价值在于它没有停留在“能跑模型”，而是把正确性验证、服务、Agent、跨 GPU 后端和 SSD streaming 组合成可审计的专用工程路径。

### 2. 实用型：microsoft/rnx-kit — 87/100

- 仓库：[microsoft/rnx-kit](https://github.com/microsoft/rnx-kit)
- 一句话定位：微软维护的一组 React Native 依赖治理、Metro 打包和跨平台工程工具。
- 类型与适合用途：成熟开发工具；适合维护 React Native monorepo、Windows/macOS/iOS/Android 多端项目及大型依赖矩阵的团队。
- 核心亮点与场景：用 `align-deps` 统一依赖版本，增强 Metro 的类型检查、tree shaking、重复与循环依赖检测，并提供跨平台构建和微软规模化默认配置。
- 主要技术栈：TypeScript、JavaScript、Kotlin、Objective-C、Swift、React Native、Metro。
- 实时指标：1,723 Stars / 119 Forks；MIT；未归档（2026-07-08 GitHub Search API 实时值）。
- 近期有意义活动：GitHub API 显示 2026-07-07 有推送；仓库页显示 2026-07-07 发布 `@react-native-webapis/web-storage@0.4.6`，已有 861 个 Release，持续维护多包版本线。
- 质量证据：3,827 次提交和 861 个 Release；包含贡献指南、RFC 流程、路线图、安全策略、文档站与 CI；README 明确说明这些工具用于微软大规模 React Native 应用交付。
- 风险：多包仓库和平台矩阵增加升级复杂度；部分原生云构建能力标为 experimental；并非所有包都适合普通单体 React Native 应用。
- 推荐理由：社区规模不算最大，但维护深度、真实生产采用、文档和长期发布纪律明显优于许多高 Star 工具，适合作为今天的成熟实用项。
