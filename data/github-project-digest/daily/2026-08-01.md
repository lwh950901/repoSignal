今天的强信号不是单纯追逐 AI 热度，而是“把 Agent 接入真实团队工作流”：`openwork` 在 Trending 日增约 796 Stars，并以跨平台桌面端、统一 MCP 与团队能力治理形成爆发点；`TencentDB-Agent-Memory` 把对话、技能、Wiki 和代码图谱沉淀为可治理资产。成熟侧由 Chatwoot 提供长期维护锚点，`tuicr` 与 Kaneo 则分别改善代码审查和项目协作的日常摩擦。

## 主推荐

### 1. 爆发型：different-ai/openwork — 91/100

- 仓库：[different-ai/openwork](https://github.com/different-ai/openwork)
- 一句话定位：跨 macOS、Windows、Linux 的开源 Agent 工作台，可把 Skills、MCP 和连接服务共享给个人或团队。

- 核心亮点与场景：通过一个 OpenWork MCP 暴露能力搜索与执行，把本地桌面工作区、团队发布、权限和连接器统一起来；既可独立使用桌面端，也可接入现有 Agent 客户端。
- 主要技术栈：TypeScript、Electron、pnpm/Turborepo、MCP、Rust 示例沙箱。
- 实时指标：19,305 Stars / 1,946 Forks；主体代码 MIT，`/ee` 目录使用 Fair Source License；未归档、非 Fork；GitHub Trending 于 2026-08-01 核验。
- 近期有意义活动：2026-07-30 发布 v0.18.12，区分 Public、Cloud 与 Enterprise 构建；2026-07-31 连续发布 0.18.13 alpha 构建，且当日 Trending 增长约 796 Stars。
- 质量证据：仓库有 docs、evals、examples、SECURITY、Code of Conduct 和多平台打包目录；4,103 次提交；Release 资产带校验值并有签名/公证说明。
- 风险：仍处在快速迭代的 Alpha 周期；Windows 安装器暂未完成生产代码签名；企业目录不是 MIT，部署前需确认功能与许可证边界。
- 推荐理由：爆发增长背后有跨平台产物、团队治理、文档和 Release 证据支撑，不是只靠“Claude Cowork 替代品”的定位炒作。

### 2. 实用型：chatwoot/chatwoot — 92/100

- 仓库：[chatwoot/chatwoot](https://github.com/chatwoot/chatwoot)
- 一句话定位：可自托管的全渠道客服平台，统一在线聊天、邮件、WhatsApp 等客户会话。
- 类型与适合用途：成熟全栈业务应用；适合需要替代 Intercom、Zendesk 或自建客服工作台的产品和支持团队。
- 核心亮点与场景：覆盖共享收件箱、自动化、团队协作、联系人与报表，并提供 Docker、云部署和多渠道集成，适合从小团队试用扩展到生产客服流程。
- 主要技术栈：Ruby on Rails、Vue/JavaScript、PostgreSQL、Redis、Docker、Playwright/RSpec。
- 实时指标：35,043 Stars / 8,432 Forks；企业目录外为 MIT Expat，企业目录另有许可证；未归档、非 Fork；GitHub Trending 与仓库页于 2026-08-01 核验。
- 近期有意义活动：v4.16.2 于 2026-07-27 发布，包含 WhatsApp 健康监控、Intercom 导入可靠性、账户限制与会话参与者安全加固，并明确建议升级获取最新安全修复。
- 质量证据：6,529 次提交；仓库含 RSpec、Playwright、Docker、部署目录、API/Swagger、贡献与安全政策；Release 给出具体安全和可靠性修复。
- 风险：系统体量大且开放 Issue/PR 较多，自托管需要维护数据库、Redis、邮件和渠道凭据；企业功能与社区版许可边界需提前核对。
- 推荐理由：它在维护密度、部署材料、测试覆盖和真实业务完整度上都很强，是今天最稳的成熟实用位，而不是按 Stars 单独排序。

- 推荐理由：体量不大但问题定义清晰、发布与真实修复证据完整，增长也有 Trending 支撑，适合作为低风险试用的潜力工具。

- 推荐理由：它把“记住对话”推进到可版本化、可授权、可装配的团队资产层，工程边界比普通 memory Demo 更完整，适合真实评估。
