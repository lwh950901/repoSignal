## 1. 爆发型：xbtlin/ai-berkshire

- **仓库**：[xbtlin/ai-berkshire](https://github.com/xbtlin/ai-berkshire)
- **一句话定位**：把价值投资研究方法拆成可供 Claude Code/Codex 执行的多 Agent Skills、检查清单和精确计算工具。
- **内容类型与适合用途**：Agent 工作流/研究方法模板，不是自动交易系统；适合学习多视角研究编排、结构化反偏见流程和可复现报告模板。
- **核心亮点与场景**：用多个独立研究角色交叉分析商业模式、估值、竞争和风险；配套 `financial_rigor.py` 等工具校验市值与单位；适合作为复杂知识工作流的设计参考。
- **主要技术栈**：Python、Markdown Skills、Claude Code/Codex、多 Agent 工作流、Mermaid。
- **实时指标**：6,601 Stars、865 Forks；MIT；未归档、非 Fork。仓库创建于 2026-04-07。
- **近期有意义活动**：GitHub 仓库 API 显示 2026-06-29 仍有推送；主分支提交页可见 2026-06-26 新增 PDD 研究覆盖度评估与信息缺口分析。2026-06-30 的 GitHub Trending 日榜中可见该项目，构成爆发型的实时趋势证据。
- **质量证据**：
  1. README 明确列出 18 个研究 Skills、三层架构、快速上手和完整示例，而非单一 Prompt。
  2. 提供使用 `decimal.Decimal` 的财务精度工具，并强调关键数据多源交叉验证。
  3. Issue 区已有对“方法是否过度拟合”“分析偏保守”“token 成本”等真实局限的讨论。
- **风险**：README 中的历史收益和账户截图无法独立证明未来效果；金融结论属于高风险场景，必须自行核验数据和假设。仓库未发现 `.github/workflows`，自动化测试/CI 证据弱；近期大量自动扫描提交也会放大表面活跃度。因此它适合当研究框架和 Agent 设计样本，不适合直接作为投资依据。
- **推荐理由**：爆发速度和结构化 Agent 设计都值得拆解，且把“多 Agent”落到了职责、检查表和工具层；风险边界清楚后，发现价值高。
- **评分拆分**：社区 24/25、维护 20/25、质量 16/20、适合度 16/20、风险 5/10，合计 **81/100**。

## 2. 实用型：alexellis/arkade

- **仓库**：[alexellis/arkade](https://github.com/alexellis/arkade)
- **一句话定位**：用一个 Go CLI 安装和更新常见开发者命令行工具与 Kubernetes 应用。
- **类型与适合用途**：成熟开发工具；适合新机器初始化、CI 环境准备、Kubernetes 实验环境和跨平台工具版本管理。
- **核心亮点与场景**：`arkade get` 覆盖 kubectl、kind、Terraform、jq 等大量 CLI，另有 Kubernetes 应用目录；降低逐个寻找安装脚本和处理平台差异的成本。
- **主要技术栈**：Go、Shell、GitHub Actions、Kubernetes/Helm/OCI。
- **实时指标**：4,595 Stars、302 Forks；MIT；未归档、非 Fork；19 个开放 Issue。
- **近期有意义活动**：2026-06-29 发布 [0.11.104](https://github.com/alexellis/arkade/releases/tag/0.11.104)，新增 `arkade search`；同日还有 OCI 安装扁平化选项相关提交。
- **质量证据**：
  1. README 列出 193 个 CLI 和 53 个 Kubernetes 应用，并提供安装、CI、OCI、Helm 与卸载示例。
  2. 仓库展示 CI Build 与 URL Checker，能持续发现失效下载地址。
  3. 项目自 2020 年持续维护，最新 Release 与提交均发生在核验日前一天，且开放 Issue 数相对克制。
- **风险**：它负责拉取第三方二进制和安装清单，供应链安全仍取决于上游 Release、校验策略和本地执行权限；生产环境应固定版本并审查下载来源。Kubernetes 应用封装无法替代对 Helm values 和升级兼容性的理解。
- **推荐理由**：价值直接、试用成本低，且成熟度、文档和发布节奏均明显高于普通“工具集合”；是今天最稳妥的效率型发现。
- **评分拆分**：社区 20/25、维护 24/25、质量 19/20、适合度 18/20、风险 9/10，合计 **90/100**。

## 3. 潜力型：trpc-group/trpc-agent-go

- **仓库**：[trpc-group/trpc-agent-go](https://github.com/trpc-group/trpc-agent-go)
- **一句话定位**：面向生产服务的 Go 原生 Agent 框架，把图工作流、工具、记忆、评测、OpenTelemetry 观测和 Agent 协议放进同一套运行时。
- **类型与适合用途**：Agent/RAG 基础设施；适合已有 Go 服务、重视并发/取消语义/可观测性，以及需要 A2A、AG-UI、MCP 接入的团队。
- **核心亮点与场景**：支持类型安全 GraphAgent、多 Agent 链式/并行流程、持久状态、Skill 加载、评测集与指标、OpenTelemetry/Langfuse，以及 MCP/A2A/AG-UI。
- **主要技术栈**：Go、OpenTelemetry、MCP、A2A、AG-UI、RAG、Langfuse。
- **实时指标**：1,429 Stars、185 Forks；Apache-2.0；未归档、非 Fork；61 个开放 Issue/PR。
- **近期有意义活动**：2026-06-29 修复评测 Prompt 迭代器取消状态竞态，并更新 benchmark；2026-06-28 加入工具描述优化并更新存在漏洞的 Go 依赖。最新正式版 [v1.10.0](https://github.com/trpc-group/trpc-agent-go/releases/tag/v1.10.0) 发布于 2026-06-05，包含 OpenAI telemetry、图节点 trace 扁平化、模型选择等改进。
- **质量证据**：
  1. README 有 Quick Start、Go API 示例、独立文档站、Go Report Card、测试与 Codecov 徽章。
  2. 评测、可观测性不是路线图占位：近期提交直接涉及评测竞态、Prompt 优化和观测文档。
  3. 活跃 PR 涉及 macOS sandbox、Web Search/Browser Eval 兼容及 DeepSeek cache token 修复，显示真实集成面正在扩展。
- **风险**：功能面很宽，API 与子系统仍可能快速变化；v1.10.0 之后主分支持续高频演进，生产采用应锁版本并先验证关键 provider、存储和 telemetry 路径。腾讯系项目背景不等于社区治理承诺，需要持续观察外部贡献者与长期兼容性。
- **推荐理由**：Go Agent 生态相对 Python/TypeScript 更稀缺；该项目已同时覆盖运行时、协议、评测和观测，工程证据强，适合做小型 PoC 后持续跟踪。
- **评分拆分**：社区 17/25、维护 25/25、质量 19/20、适合度 19/20、风险 8/10，合计 **88/100**。
