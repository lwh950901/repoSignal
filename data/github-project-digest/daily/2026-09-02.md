## 主推荐

### 1. 爆发型：browser-use/video-use — 91/100

- 仓库：[browser-use/video-use](https://github.com/browser-use/video-use)
- 一句话定位：让 Claude Code、Codex 等 coding agent 通过结构化转录、时间线和 FFmpeg 编辑视频并输出可复核的成片。
- 类型与适合用途：爆发型；适合内容团队、独立开发者和想把视频剪辑纳入 Agent 工作流的人，用于短视频、教程、访谈和发布视频的半自动制作。
- 核心亮点与场景：GitHub Trending 2026-09-02 约新增 509 Stars；项目用 word-level transcript、按需 filmstrip/waveform、EDL、并行动画子 Agent 和 cut-boundary self-eval，避免把数万帧直接塞给模型，适合先做一条可审计的“转录—决策—渲染—复核”链路。
- 主要技术栈：Python、Claude Code/Codex skill、ElevenLabs Scribe、FFmpeg、PIL、Remotion、Manim、HyperFrames。
- 实时指标：截至 2026-09-02 GitHub Trending/仓库页约 22,774 Stars、2,800 Forks；MIT；公开仓库，未归档。
- 近期有意义活动：Trending 当日约新增 509 Stars；提交页可核验 2026-08-30 的音频轨选择与静音拒绝、竖屏旋转元数据、帧率保持修复；仓库约 21 commits，Release 页当前没有正式 Release。
- 质量证据：README 提供 `install.md`、`SKILL.md`、`helpers/`、`tests/` 和 `uv sync`/FFmpeg 安装入口；明确描述 transcript + on-demand visual 的架构与 `Transcribe → Pack → LLM Reasons → EDL → Render → Self-Eval` 流程；MIT LICENSE 已存在。
- 风险：依赖 ElevenLabs API key、FFmpeg 和具体 Agent shell 权限；项目仍早期且没有正式 Release，成片质量、字幕/音频结果和成本需要用自己的素材回归，不能把自评循环当成专业剪辑审核。
- 推荐理由：它同时满足爆发型的 5,000+ Stars 与日期明确的 Trending 加速证据，并且技术亮点不是营销式“AI 剪视频”，而是把视觉输入压缩成可解释的文本与时间线状态；值得亲自跑一段短素材验证。

- 一句话定位：用于 JavaScript/TypeScript 的轻量多 Agent、工具调用、沙箱和实时语音 Agent SDK。

- 核心亮点与场景：同一套 API 覆盖普通 text agent、带文件系统/命令执行能力的 sandbox agent 和浏览器实时语音 agent；工具、MCP、会话、审批与 tracing 有清楚的组合边界，适合从一个小工具逐步扩展为多 Agent 工作流。

- 风险：沙箱、实时语音和 MCP 仍有 beta/供应商依赖；API 版本变化较快，生产环境应固定版本、限制文件/网络权限、为 tool output 和凭据做额外审计，不应直接照搬 README 中的宽权限本地示例。

### 3. 潜力型：bubbuild/bub — 89/100

- 仓库：[bubbuild/bub](https://github.com/bubbuild/bub)
- 一句话定位：以 hook-first 和 append-only tape context 为核心、让人和 Agent 在同一环境协作的轻量 Python runtime。
- 类型与适合用途：潜力型；适合二次开发多渠道 Agent、可审计会话、插件化 turn pipeline 和人机协作入口，不适合直接当作成熟企业平台替代品。
- 核心亮点与场景：`resolve_session → load_state → build_prompt → run_model → save_state → render_outbound → dispatch_outbound` 每一阶段都是可替换 hook；同一 runtime 支持 CLI、Telegram 和自定义 channel，适合实验“运行时边界由插件扩展、状态由记录重建”的 Agent 产品形态。
- 主要技术栈：Python 3、pluggy、uv、Agent Skills、AGENTS.md、CLI、Telegram、Docker/Compose。
- 实时指标：截至 2026-09-02 GitHub Search/仓库页约 1,595 Stars、156 Forks；Apache-2.0；公开仓库，未归档。
- 近期有意义活动：GitHub Search 当前 `pushed_at` 为 2026-09-01T14:26:01Z；仓库页约 504 commits，并显示持续的 Issue/PR 与 Actions 入口。
- 质量证据：README 提供安装脚本、`uv sync`、`bub chat`/`bub run`/`bub gateway` 运行入口和插件示例；源码入口明确指向 `framework.py`、`hooks/specs.py`、`builtin/hook_impl.py` 与 `skills.py`；开发命令包含 `make check`、`make test`、`make docs-test`。
- 风险：社区规模仍小，模型默认配置、插件依赖和多渠道边界会快速变化；append-only tape 并不自动解决隐私、删除权或并发一致性，部署前要检查日志留存、密钥传递和插件权限。
- 推荐理由：它的价值在清楚而可扩展的 runtime 抽象，而不是 Stars 数量；hook contract、state reconstruction 和 operator equivalence 都有具体源码入口，适合从一个自定义 `build_prompt`/`run_model` 插件开始验证二次开发路径。
