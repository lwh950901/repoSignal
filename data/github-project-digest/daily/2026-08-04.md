### 1. 爆发型：firecrawl/pdf-inspector — 93/100

- 仓库：[firecrawl/pdf-inspector](https://github.com/firecrawl/pdf-inspector)
- 一句话定位：用纯 Rust 在本地分类 PDF、抽取带位置信息的文本并转换为结构化 Markdown。
- 类型与适合用途：PDF 解析库与 CLI；适合 RAG 文档预处理、OCR 智能分流、报告/论文/票据抽取和浏览器端 PDF 工具。
- 核心亮点与场景：先判断文本型、扫描型、图像型或混合型 PDF，再对可直接解析的页面完成多栏阅读顺序、表格、标题、列表和链接恢复，避免所有文档都走昂贵 OCR。
- 主要技术栈：Rust、lopdf、PyO3、N-API、WebAssembly、Python、Node.js。
- 实时指标：7,952 Stars / 532 Forks，MIT；仓库未归档；GitHub Trending 同轮显示当日约增 1,769 Stars。
- 近期有意义活动：2026-08-03 提交将 lopdf 升至 0.42.0，修复嵌套 PDF 触发的 RUSTSEC-2026-0187 拒绝服务风险；同日还升级并按 SHA 固定发布工作流中的 GitHub Actions。
- 质量证据：提供 Rust、Python、Node.js、浏览器 WASM 与 CLI 四类入口；公开 200 份 PDF 的可复现实验、成对基准工具与逐文档结果；README 给出模块架构、调试方式和独立语言文档。
- 风险：它不执行 OCR，扫描件仍需外部分流；公开基准由项目方维护且语料规模有限，复杂字体、恶意 PDF 与超大文件仍应在隔离环境中用自有数据压测。
- 推荐理由：当日增长极强，但真正拉开差距的是可复现基准、多语言绑定、清晰架构和快速安全响应，兼具直接使用与二次开发价值。
