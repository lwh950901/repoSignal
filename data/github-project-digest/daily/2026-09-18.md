## 主推荐

### 1. 实用型：superplanehq/superplane — 87/100

- 仓库：[superplanehq/superplane](https://github.com/superplanehq/superplane)
- 一句话定位：把高置信度 backlog 工作转成可审查 PR 的开源工程自动化控制面。
- 类型与适合用途：实用型；适合希望把编码 Agent、CI、审批和人工复核纳入一个可观测流程的研发团队。
- 核心亮点与场景：以 Factory、Work order、Line 与 Run 表达可恢复的工作流；覆盖 Agent、源码管理、CI、云与可观测性集成，适合从单个重复性 Issue 自动化开始。
- 主要技术栈：Go、React、Kubernetes、事件驱动工作流。
- 实时指标：7,501 Stars、639 Forks、Apache-2.0；同轮 GitHub 搜索显示 2026-09-17 有代码推送。
- 近期有意义活动：仓库页列出 3,245 次提交、Docker 开发/CI 配置、测试目录与贡献流程；2026-09-17 的更新表明仍在维护。
- 质量证据：Apache-2.0 许可证；`docs/`、`api/swagger/`、`test/`、Docker 开发与 CI 配置齐备；README 说明可在云端或本地运行并保留执行状态与工件。
- 风险：系统边界很大、待处理 Issue/PR 数量高；接入生产前需先验证权限模型、成本控制和失败恢复策略。
- 推荐理由：工程化边界清晰，既有可部署路径又将人工判断留在审批环节，是当前最适合作为团队 Agent 平台试点的项目。

- 核心亮点与场景：23 章沿“工具→记忆→规划→RAG→评估→安全→部署”递进，附可运行 reference agent，可将其中的模块逐步移植到自己的原型。

- 核心亮点与场景：Queen 与 Worker 共享账本和持久计划；提供崩溃安全的暂停/恢复、成本约束、浏览器使用与人工介入，适合抽取执行控制层的设计。

- 风险：开放 Issue/PR 数量很高，且运行时的“零配置”承诺仍需按真实模型、权限和浏览器策略验证；不宜直接把生产凭据交给默认流程。
