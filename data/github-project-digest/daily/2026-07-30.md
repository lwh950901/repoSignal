# GitHub 优质项目每日发现｜2026-07-30

> 今日重点：把 Agent 质量、成本与代码审查变成可复核的工程闭环，同时保留成熟业务工具和跨领域 GIS 的正式位置。

## 今日结论

今天的强信号不是单纯“又一个 Agent”，而是可审计的工程配套：`open-code-review` 在一个月内显著增长并进入 v1.8.0，`better-harness` 把 Agent 改进变成带 860 项测试的评测流程，`agentacct` 则补上本地成本与工作证据账本。跨领域方面，GeoLibre 当日增长明显且发布了包含 H3/STAC 插件的 v2.4.0；Snipe-IT 证明成熟、非 AI 的自托管工具仍值得占据实用位。

## 主推荐

### 1. 爆发型：alibaba/open-code-review — 92/100

- 仓库：[alibaba/open-code-review](https://github.com/alibaba/open-code-review)
- 一句话定位：把确定性静态规则与 LLM Agent 结合的仓库级代码审查工具，可输出精确到行的审查意见。
- 类型与适合用途：Go 编写的代码质量/DevSecOps 工具；适合希望在 GitHub、GitLab、CodeUp、VS Code 或编码 Agent 流程中加入可审计审查的团队。
- 核心亮点与场景：规则管线负责 NPE、线程安全、XSS、SQL 注入等确定性问题，Agent 负责上下文判断；v1.8.0 又增加远程 MCP、Terraform/Bicep 与评论路由控制，适合 PR 门禁和本地预审。
- 主要技术栈：Go、TypeScript/VS Code Extension、GitHub Actions、MCP、OpenAI/Anthropic 兼容接口。
- 实时指标：15,951 Stars / 1,077 Forks；Apache-2.0；未归档、非 Fork；GitHub Scanner 于 2026-07-30 实时核验。
- 近期有意义活动：v1.8.0 于 2026-07-28 发布，加入远程 MCP、HCL/Terraform/Bicep 支持并修复 js-yaml 安全问题；2026-07-29 提交继续增加 fail-open 严重度路由、Prisma 审查和带 27 项测试的 CodeUp CI 集成。
- 质量证据：README enrich 命中安装、许可证、测试和 substantial 文档；v1.8.0 有明确功能/修复/安全变更与 9 个构建资产；提交把外部 CI 集成拆成可测试模块。
- 风险：项目仍只有约两个半月历史，70 个开放 Issue 需要持续观察；LLM 审查仍有成本、误报和提示注入风险，不能替代确定性测试与人工审批。
- 推荐理由：它在 2026-07-04 首次推荐时为 9,884 Stars，如今增长约 61%，且今日 Trending 再增约 386 Stars；显著增长、v1.8.0 和安全/集成扩展共同满足 90 天重复破例，不是简单复读热门项目。

### 5. 潜力型：mikehasa/agentacct — 85/100

- 仓库：[mikehasa/agentacct](https://github.com/mikehasa/agentacct)
- 一句话定位：本地记录编码 Agent 做了什么、花了多少时间和 Token、改了哪些文件并跑了哪些测试的工作证据账本。
- 类型与适合用途：本地优先 Agent 可观测性/成本分析工具；适合同时使用 Claude Code、Codex、OpenCode 等工具的个人和小团队复盘任务成本与验证质量。
- 核心亮点与场景：把会话拆成工作步骤并关联工具、文件、测试、耗时与成本，不需要登录或遥测；可用 dashboard、CLI 和 MCP 检查阻塞项、证据和活动轨迹。
- 主要技术栈：Python、FastAPI/本地 Web Dashboard、SQLite/本地事件存储、MCP、CLI。
- 实时指标：526 Stars / 53 Forks；MIT；未归档、非 Fork；GitHub Scanner 于 2026-07-30 实时核验。
- 近期有意义活动：v0.5.1 于 2026-07-30 发布，将 `AGENTACCT_*` 作为新环境变量前缀，同时永久兼容旧别名并拒绝冲突路径；此前 v0.4.0 改为默认机器级安装且不写入仓库。
- 质量证据：README enrich 命中安装、用法、许可证、测试和 substantial 文档；Release 遵循 changelog/语义化版本说明；升级保留历史事件 schema 与旧环境变量读取兼容。
- 风险：项目创建不足一周、主要由单一维护者驱动，v0.x API 和数据语义仍可能快速变化；会话日志即使本地保存也可能含敏感路径或命令，需要审查脱敏与保留策略。
- 推荐理由：它不与 Agent 本体竞争，而是补上成本、证据和复盘层；问题明确、上手成本低，维护者又主动处理重命名兼容和零仓库写入，适合小范围真实试用。
