**差异化**：对比单 Agent 工具，它把多 Agent 的会话、审批、审计、成本收到一个控制面里。

**MVP 范围（做什么，不含代码）**：接一个 Agent 宿主 + 一个协作渠道 + 审计日志，验证审批、打断、失败恢复三个动作，再扩展多 Agent。

**主要风险（来源报告）**：

- `spinframework/spin`（多 Agent 编排）：WASI 和 Component Model 仍在演进，语言能力矩阵并不完全一致；canary 与宿主扩展接口不宜直接作为稳定生产合同照搬。
- `ayghri/i-have-adhd`（通信/协作入口）：强制短答可能压缩必要证据或不适合教学、审计和高风险任务；名称涉及 ADHD，但工具不是医学建议或诊断方法。
- `hyperdxio/hyperdx`（会话观测与审计）：部署复杂度高，ClickHouse/OTel/collector 运维成本不可忽略；开源产品与 ClickHouse/HyperDX 商业生态绑定，长期路线需关注。
- `nvidia-nemo/switchyard`（模型路由/成本）：README 明确标注 pre-alpha、API 和算法会显著变化、不可用于生产；协议转换错误、路由延迟和 provider 行为差异可能放大成本与可靠性问题。
- `akitaonrails/ai-memory`（共享记忆）：自动改进默认可能产生待写入记忆，hooks 会接触 Agent 会话上下文，凭证捕获/脱敏和跨项目隔离必须先审查；原生 Windows 仍标为 experimental…
