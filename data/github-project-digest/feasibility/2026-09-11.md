**MVP 范围（做什么，不含代码）**：接一个 Agent 宿主 + 一个协作渠道 + 审计日志，验证审批、打断、失败恢复三个动作，再扩展多 Agent。

**主要风险（来源报告）**：

- `simstudioai/sim`（多 Agent 编排）：真实生产部署仍需单独评估模型费用、密钥管理、工作流权限和持久化数据隔离；大而全的 Agent 平台也可能引入不必要的运维面。
- `nousresearch/hermes-agent`（通信/协作入口）：社区和变更规模极大，开放 Issue/PR 数量也很高；安装脚本、模型凭据、消息渠道权限和自动更新需要隔离验证，不建议直接把自主运行权限交给敏感账户。
- `hyperdxio/hyperdx`（会话观测与审计）：部署复杂度高，ClickHouse/OTel/collector 运维成本不可忽略；开源产品与 ClickHouse/HyperDX 商业生态绑定，长期路线需关注。
- `justvugg/colibri`（模型路由/成本）：硬件兼容性、模型格式、量化质量和性能数字高度依赖具体环境；为极限内存占用做的同步 I/O、错误处理和接口取舍不应直接照搬到通用生产服务。
- `akitaonrails/ai-memory`（共享记忆）：自动改进默认可能产生待写入记忆，hooks 会接触 Agent 会话上下文，凭证捕获/脱敏和跨项目隔离必须先审查；原生 Windows 仍标为 experimental…
