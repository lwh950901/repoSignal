**差异化**：对比传统 SAST 只报问题，它把'扫描 + 修复建议 + 独立验证'做成完整流程，且每一步有证据。

**MVP 范围（做什么，不含代码）**：在授权靶场跑'扫描→修复建议→独立验证'三步，保留证据与人工审批，再评估接入正式仓库。

**主要风险（来源报告）**：

- `openai/codex-security`（安全审计/扫描）：部分网络安全请求和受保护发现需要 Trusted Access for Cyber；扫描依赖模型、API 权限和成本，不能替代静态分析、依赖扫描、人工审计或完整测试；早期 0.1.x…
- `containers/ramalama`（隔离执行）：容器隔离不消除模型供应链、GPU 驱动和远程代码风险；示例默认值不宜直接照搬到共享 GPU 或生产网络。
- `waishnav/devspace`（Agent 编排）：并行 Agent 会放大分支冲突、凭据暴露和不可复现操作；不能把隔离工作区误当成安全沙箱。
- `getmaxun/maxun`（代码理解）：网页条款、robots、登录凭据、代理来源和个人数据处理需要单独合规；AGPL 会影响闭源服务集成，自动恢复也不能保证页面改版后数据仍正确。
- `sammcj/mcp-devtools`（证据与报告）：社区规模小，近期大量提交是依赖更新；工具集合型项目要按实际启用工具逐项审计权限边界。
