# 开源雷达周刊

![开源雷达周刊｜每周开源项目精选](/covers/repository-radar-weekly-subtitle.png)

这一周的日报集中出现了几条清晰线索：Agent 开始进入设计和教育等具体工作流，技能本身也有了评测与优化工具；与此同时，本地优先的软件仍然是最容易亲自验证的一类项目。

周报从 18 个主推荐和 4 个额外发现中留下 10 个项目。它们并不都属于同一赛道，但共同点很一致：已有可以运行的产品形态，也明确暴露了权限、隐私或稳定性边界。

## 一、Agent 进入设计与学习场景

### 1. open-design：把设计系统和 Agent 放进同一工作台

[open-design](https://github.com/nexu-io/open-design) 将设计系统、MCP、Agent 工具、插件和多格式导出整合到一个开源设计工作台。它既可以生成原型，也可以把 `DESIGN.md`、HTML、PPT 和 PDF 等产物纳入同一流程。

**适合：** 希望让 Agent 参与原型、设计资产和前端交付，同时保留品牌约束的团队。

**注意：** 项目增长很快，Issue 和 PR 队列也较大。桌面端稳定性、导出一致性、模型费用以及 bundled skills 的许可证都需要在正式接入前逐项核对。

### 2. DeepTutor：一套可以部署的开源 AI 导师

[DeepTutor](https://github.com/HKUDS/DeepTutor) 把 RAG、长期记忆、测验、研究能力和多渠道集成组合成完整教育产品。相比单个问答 Demo，它已经包含后端、Web 前端、知识库和部署材料。

**适合：** 想用自有课程或研究文档搭建学习助手的教育团队和个人开发者。

**注意：** 功能和依赖矩阵很大，部署升级并不轻。学习答案和测验仍受模型幻觉影响，真实学生数据、长期记忆和外部渠道接入前必须先解决隐私与权限问题。

## 二、技能优化与统一数据访问

### 3. SkillOpt：让 Agent 技能通过任务结果迭代

[SkillOpt](https://github.com/microsoft/SkillOpt) 根据任务轨迹、评分和验证门控优化技能文本，最终输出可部署的 `best_skill.md`，不需要修改模型权重。它把“凭感觉改提示词”变成一套可以回放和比较的流程。

**适合：** 已有稳定 Agent 任务，希望持续改进团队技能库的人。

**注意：** 优化结果高度依赖任务集、奖励函数和验证集；工具还会读取 Agent 会话。开始前应做好密钥脱敏，并用 held-out 任务防止技能只适配训练样本。

### 4. mirage：把不同数据后端变成 Agent 熟悉的文件系统

[mirage](https://github.com/strukto-ai/mirage) 将 S3、Google Drive、Slack、Gmail、Redis、数据库等后端统一为可以通过 `grep`、`cp`、`cat` 操作的虚拟文件系统。对 Agent 来说，这比为每种数据源维护不同工具接口更容易组合。

**适合：** 正在搭建 Agent 数据访问层，需要同时连接多个存储和 SaaS 服务的团队。

**注意：** 凭据集中会放大权限和数据外泄风险，文件系统抽象也可能掩盖真实审计边界。建议先从 RAM、Disk 或低敏感 bucket 开始，不要一开始接入 Gmail 和 Slack。

## 三、本地优先的意外发现

### 5. OpenLogi：不登录账号也能管理 Logitech 设备

[OpenLogi](https://github.com/AprilNEA/OpenLogi) 是一个本地优先的 Logitech 设备管理工具，提供 GUI 和 CLI，可配置按键、DPI、滚轮等行为，支持 Linux 和 Windows。它不依赖账号，也默认没有遥测。

**适合：** 希望替代厂商管理软件，或需要用配置文件管理多台设备的用户。

**注意：** 项目仍在快速开发，设备、接收器和固件组合很多，Windows 支持也较新。应先在非关键设备上备份配置并逐项验证；二次分发还要避开未授权的品牌资产。

## 四、面向真实工作流的工程工具

### 6. MiMo-Code：支持技能和多模型的终端编码 Agent

[MiMo-Code](https://github.com/XiaomiMiMo/MiMo-Code) 在终端里提供编码 Agent、技能、多模型和多 Agent 能力。它适合拿来比较不同模型配置与长任务执行方式，而不必先搭建独立平台。

**适合：** 想在隔离仓库比较多模型编码效果的开发者。

**注意：** 仍处于 0.1.x，Windows、重复检测和长任务稳定性需要重点验证，并应限制文件与命令权限。

### 7. rnx-kit：治理 React Native 的依赖和构建差异

[rnx-kit](https://github.com/microsoft/rnx-kit) 是 Microsoft 维护的 React Native 工具集，覆盖依赖对齐、Metro 配置和跨平台工程检查，适合复杂 monorepo 减少版本漂移。

**适合：** 同时维护多个 React Native 应用或包的平台团队。

**注意：** 工具链和平台矩阵较复杂；简单单应用可以先只试 `align-deps`，不必一次引入全部能力。

### 8. DevSpace：缩短 Kubernetes 开发循环

[DevSpace](https://github.com/devspace-sh/devspace) 用一个 CLI 处理构建、部署、文件同步、热更新和集群内调试。它是一个成熟的云原生开发工具，能把频繁的镜像构建与部署等待压缩成更短的反馈循环。

**适合：** 日常在 Kubernetes 开发环境调试服务的团队。

**注意：** 需要处理集群版本、Helm chart 和本地配置兼容；先接入一个开发服务并验证回滚，再扩大范围。

### 9. omnigent：把多个编码 Agent 放进协作控制面

[omnigent](https://github.com/omnigent-ai/omnigent) 统一管理 Codex、Claude Code、Cursor 等会话，并提供子代理、reviewer、审批策略和协作入口，关注的是如何治理已有 Agent，而不是再造模型框架。

**适合：** 同时使用多个编码 Agent、希望增加评审与审批记录的团队。

**注意：** 项目仍在 alpha，集成面和权限面很大；应先用一个 Agent、一个 reviewer 和隔离任务验证中断与恢复。

### 10. listmonk：自托管 Newsletter 与邮件列表

[listmonk](https://github.com/knadh/listmonk) 以单一二进制、PostgreSQL 和管理后台提供邮件列表、模板、分群与发送能力。它成熟、可部署，也与开源周刊的内容分发场景直接相关。

**适合：** 希望掌握订阅者数据和邮件发送基础设施的内容团队。

**注意：** 送达率、退订合规、SMTP 声誉、备份和 AGPL 义务仍由部署者负责，先用测试名单跑完整流程。

## 本周优先试用

如果只选一个：

- 做设计与前端协作，可以用 **open-design** 跑一次真实原型；
- 维护 Agent 技能，可以给 **SkillOpt** 准备一组小型对照任务；
- 想试一个不依赖模型的工具，可以从 **OpenLogi** 开始。

完整周报保留了各项目的维护证据、版本差异、许可证和更具体的试用路径。
