## 入选 1：本地优先个人 AI 工作台

- 原始方案标题：本地优先个人 AI 工作台（组合 5 个项目，今日锚点 2 个）。
- 原始方案评分：83/100（中）；组件可靠度 30/35、组件供给 13/15、风险敞口 12/15、今日锚点 10/15、来源多样性 8/10、许可证 5/5、完整度 5/5。
- 原始来源文件：2026-08-24、2026-08-25、2026-08-29、2026-08-30；发布基线取 2026-08-30 的最高分版本。
- 业务定位：数据全部留在本机、模型可自由切换、记忆可导出的个人 AI 工作台。
- 目标客户：重视隐私的个人开发者、知识工作者与小型团队。
- 市场机会：池里本地优先、自托管类项目反复出现（记忆/桌面/网关），个人为“数据不离开本机”付费的趋势在上升。
- 为什么现在可行：本地记忆、模型网关、Agent 编排在池里都能找到；当日锚点为 FreeLLMAPI 和 ADK Go，池内最稀缺能力面仍有 72 个候选。
- 差异化：相对云端工作台强调无云依赖和数据所有权；相对单点记忆工具强调完整工作台。
- 原始 MVP：先跑通“本地记忆写入 → Agent 读取 → 输出压缩”，再决定桌面端与多渠道接入。
- 原始验证路径：固定版本、隔离环境、自有数据复测各组件。

|---|---|---|---|
| 本地优先/桌面形态 | tashfeenahmed/freellmapi | MIT | 将多 provider 切换、限额与兼容性摩擦压缩为一次可运行本地部署。 |
| Agent 编排 | google/adk-go | Apache-2.0 | 安装、示例、文档、CI、Release 与近期维护同时强。 |
| 长期记忆 | lyellr88/marm-memory | Apache-2.0 | 语义召回与精确配置检索组合的边界清楚。 |
| 模型接入/网关 | google/adk-python | Apache-2.0 | 安装、样例、CI、文档与稳定 Release 完整。 |
| 本地知识检索 | topoteretes/cognee | Apache-2.0 | Agent 记忆、图谱检索、MCP 与本地/云部署可试用。 |

原始主要风险逐项保留：FreeLLMAPI 仅适合个人试验，Provider ToS、配额、延迟、可用性与自更新需审计；ADK Go 偏 Gemini/Google Cloud，模型/部署、凭据、费用与 API 需回归；MARM 社区较小且 SQLite/embedding 迁移有升级风险；ADK Python 2.0 的 API/event/session 兼容性有限且可能有 provider lock-in；Cognee 的数据隔离、LLM 成本、图/向量后端与 release note 准确性要复测。

## 入选 2：安全 Agent 平台（扫描-修复-验证）

- 原始方案标题：安全 Agent 平台（扫描-修复-验证）（组合 5 个项目，今日锚点 1 个）。
- 原始方案评分：79/100（中）；组件可靠度 31/35、组件供给 14/15、风险敞口 9/15、今日锚点 5/15、来源多样性 10/10、许可证 5/5、完整度 5/5。
- 原始来源文件：2026-08-25、2026-08-26、2026-08-28、2026-08-30；发布基线取 2026-08-28 版本。
- 业务定位：让安全扫描由 Agent 自动跑：扫描、修复建议、独立验证和人工审批都留下证据。
- 目标客户：企业安全团队、DevSecOps 平台组。
- 市场机会：Agent 带来 Skill/MCP/供应链攻击面，安全类项目密集出现。
- 为什么现在可行：安全审计、沙箱、代码理解和观测组件可形成扫描→修复→验证数据流；池内最稀缺 codeintel 仍有 85 个候选。
- 差异化：相对传统 SAST 只报问题，强调带证据的扫描、修复建议与独立验证。
- 原始 MVP：授权靶场跑三步并保留证据与人工审批，再考虑正式仓库。
- 原始验证路径：固定版本、隔离环境、自有数据复测各组件。

| 原始角色 | 原始仓库 | 许可证 | 原始入选理由 |
|---|---|---|---|
| 安全审计/扫描 | tencent/ai-infra-guard | Apache-2.0 | 将 Agent 生态安全拆成可组合扫描面，适合内部基线。 |
| 隔离执行 | google/gvisor | Apache-2.0 | 给 Agent 任务提供可审查的用户态内核/OCI 隔离取舍。 |
| Agent 编排 | ruvnet/ruflo | MIT | 执行、记忆、路由和安全护栏可拆分。 |
| 代码理解 | tirth8205/code-review-graph | MIT | 基于 Tree-sitter/图/MCP 生成变更影响裁剪上下文。 |
| 证据与报告 | comet-ml/opik | Apache-2.0 | 自托管 trace、评测和 CI 路径补齐质量闭环。 |

原始主要风险逐项保留：AI-Infra-Guard 的规则覆盖、误报/漏报、漏洞库和权限不能当完备安全证明；gVisor 的 syscall 覆盖、性能和 Linux/Bazel 约束须按威胁模型重测；Ruflo 的 alpha/beta、插件、默认权限与 federation 边界复杂；code-review-graph 的 65x 为中位数、recall 有循环上界且小改动未必受益；Opik 会接触 prompt/输出，需存储、权限、脱敏、保留和人工评测治理。
