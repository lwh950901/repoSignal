# 最新一期入口重定向设计

## 背景

RepoSignal 当前为月报、周报、日报和开源雷达周刊同时提供无日期入口与带日期详情页。四个无日期入口的行为不一致：月报入口直接渲染最新内容，其余入口显示“打开最新一期”的链接。这会产生重复内容地址，并让用户多一次点击才能进入稳定的带日期页面。

## 目标

- `/monthly/`、`/weekly/`、`/daily/`、`/radar/` 都自动进入各自最新一期的带日期路径。
- 线上由 Cloudflare 返回临时重定向，地址栏更新为稳定详情页 URL。
- 最新一期随每次构建自动更新，不需要人工维护日期。
- 本地开发和静态部署保持相同的目标解析规则。

## 非目标

- 不修改报告 Markdown 格式、内容发现顺序或详情页路由。
- 不新增无数据状态；项目约束保证四类报告均存在。
- 不使用永久重定向、客户端 JavaScript 跳转或 CSP 例外。

## 方案

### 路由行为

四个 `src/pages/<period>/index.astro` 入口分别加载对应报告列表，取已经按时间倒序排列的第一项，并返回临时重定向：

| 入口 | 目标示例 |
| --- | --- |
| `/monthly/` | `/monthly/2026-07/` |
| `/weekly/` | `/weekly/2026-W31/` |
| `/daily/` | `/daily/2026-08-03/` |
| `/radar/` | `/radar/2026-W31/` |

重定向状态使用 `302`。目标会随新一期发布而变化，因此不能使用容易被浏览器和 CDN 长期缓存的 `301`。

### Cloudflare 静态部署

Astro 静态输出自身不能保证托管平台返回真实 HTTP 重定向。新增构建脚本，在 Astro 完成页面生成后，根据四类报告的最新 slug 写入 `dist/_redirects`。规则只匹配四个无日期入口，不匹配带日期详情页。

构建命令将串联 Astro 构建和重定向生成步骤。生成器必须确定性输出，并在任一分类缺少最新 slug 时失败，避免部署无效跳转。

### 单一数据规则

路由和 Cloudflare 规则必须使用与现有报告发现函数相同的倒序语义。重定向生成逻辑可以读取构建产物中已生成的详情目录，选择满足现有 slug 格式的最新目录，避免建立第二套 Markdown 解析器。

## 错误处理

- 四个分类任何一个没有可用详情目录时，构建脚本以非零状态退出并指出缺失分类。
- 生成脚本只写入 `dist/_redirects`，不修改 `public/`、报告数据或源 Markdown。
- 已有 `_headers` 保持不变。

## 测试与验收

- 先增加失败测试，断言四个 index 路由返回临时重定向而不是渲染正文或链接。
- 增加生成器自检，覆盖四类最新目录选择、`302` 状态、缺少分类时失败，以及规则不匹配带日期路径。
- 生产构建后确认 `dist/_redirects` 存在且四个目标均为当前最新一期。
- 运行完整 Vitest、Astro check 和生产构建。

## 预期结果

用户访问任一无日期入口时，Cloudflare 立即返回临时重定向并将地址栏更新为当前最新一期的稳定详情页。所有正文只通过带日期路径呈现。
