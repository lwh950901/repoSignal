# 月报机会发现流程简介设计

## 目标

在“真实业务与项目机会”章节标题下方，用简短文字说明机会发现流程，并在首次出现时解释 L2、L3。

## 方案

复用 `MonthlyReportView.astro` 现有章节标题区，把简介移到标题正下方并切换为单列布局；不新增 Markdown 字段、解析逻辑、依赖或组件。

采用文案：

> 先从本月仓库中寻找可组合的能力，再核对需求证据、商业产品、开源替代和现实人工流程。至少一个核心仓库需跑通单仓库核心流程（L2）；随后尝试让两个以上仓库用真实格式数据完成连接（L3），未跑通则明确降级。

简介下方、机会卡片之前增加语义化有序列表，标题为“发现流程”。桌面端横向四列，360px 纵向排列：

1. **仓库盘点**：汇总当月日报、周报、候选账本和研究材料，去重后筛出值得继续核实的仓库。
2. **需求核实**：寻找至少两类独立需求证据，并调查商业产品、开源或自托管替代，以及现实人工流程。
3. **组合设计**：选择 2–5 个职责不重叠的仓库，核对接口、输入输出、许可证、部署限制和需要自行开发的部分。
4. **验证发布**：至少一个核心仓库达到 L2，并尝试安全的 L3 组合验证；未达到门槛则降级或不发布。

## 验收

- 章节标题与机会卡片结构保持不变。
- 简介在静态 HTML 中可读，不依赖 JavaScript。
- 四步流程在静态 HTML 中按 01–04 顺序出现。
- 桌面端与 360px 视口正常换行且无横向溢出。
- 聚焦测试、Astro check 和生产构建通过。

## 非目标

- 不为每个机会新增副标题。
- 不增加每月可配置字段。
- 不改变 L0–L4 合同或机会发布门槛。
