# GitHub 项目发现站设计

## 目标

把 `data/github-project-digest` 中持续生成的每日与每周 Markdown 报告，发布为适合开发者浏览的静态网站。第一版的核心任务是让访客快速理解今日推荐，并能通过日期、关键词和技术标签找到历史项目。

## 视觉方向

采用“研究档案库 + 命令面板”的组合方向。

- 页面整体像一份持续更新的项目研究档案，而不是卡片式产品目录。
- 左侧日期轴表达真实时间关系；右侧连续条目呈现推荐项目。
- `爆发型 / 实用型 / 潜力型` 使用档案印章式标记，成为唯一醒目的视觉签名。
- `⌘K` 打开命令搜索，可按仓库名、技术栈、类型和描述筛选项目。
- 不使用大面积渐变、装饰性数据仪表盘、终端拟态或无意义编号。

### 设计令牌

- 纸白：`#F3F5F2`
- 墨黑：`#17201B`
- 苔绿：`#56705E`
- 标记黄：`#E4C95A`
- 分隔灰：`#CFD5D0`
- 中文正文：系统中文无衬线字体栈
- 标题与正文：`Inter` 回退至系统字体
- 仓库名、日期与指标：`IBM Plex Mono` 回退至等宽字体

## 页面结构

### 首页

顶部包含站点名称、当前报告日期、周精选入口和搜索按钮。主体为两栏：左侧显示可用日期与周精选入口，右侧展示当前日报的主题、结论、三个主推荐和“今天最值得试用”。

桌面端左侧日期轴固定在可视区域；移动端收拢为顶部日期选择器。项目内容使用连续档案条目，不嵌套多层卡片。

### 历史浏览

日期轴切换日报。周精选使用相同阅读结构，但弱化项目类型印章，突出精选理由与上手建议。

### 命令搜索

点击搜索或按 `⌘K` / `Ctrl+K` 打开搜索层。输入后即时匹配仓库名、定位描述、技术栈和项目类型；方向键移动，回车进入对应日期的项目位置，Esc 关闭。

第一版全部在浏览器本地完成，不引入搜索服务或数据库。

## 数据与组件

构建时读取：

- `data/github-project-digest/daily/*.md`
- `data/github-project-digest/weekly/*.md`

解析报告日期、主题、主推荐标题、仓库链接、评分、定位、技术栈、风险和推荐理由。原始 Markdown 正文仍作为详情内容，避免丢失信息。

主要界面单元：站点框架、日期导航、报告标题、项目档案条目、类型印章、指标列表、搜索面板和空状态。各单元只接收解析后的数据，不直接读取文件。

## 异常与降级

- 某份报告解析不完整时，保留原始 Markdown 内容并隐藏缺失字段，不阻断整个构建。
- 没有日报时显示明确空状态和预期数据目录。
- JavaScript 不可用时仍能阅读首页与历史页面；命令搜索不可用但普通导航保留。
- 外部字体加载失败时使用系统字体，不影响布局和阅读。

## 响应式与无障碍

- 支持窄至 360px 的移动屏幕。
- 所有交互具备可见键盘焦点。
- 搜索面板使用正确的对话框语义并支持键盘关闭。
- 尊重 `prefers-reduced-motion`；动效仅用于日期切换与搜索层出现。
- 正文、标签和交互文本满足基础颜色对比要求。

## 第一版范围

包含首页、日报/周报浏览、本地搜索、响应式布局和 Cloudflare Pages 可部署构建。

暂不包含账号、云端收藏、评论、后台管理、实时 GitHub API、复杂关系图和用户行为分析。反馈入口可在后续版本接入。

## 验收标准

- 当前日报和历史 Markdown 均能构建为可访问页面。
- 首页能清楚区分三种推荐类型，并显示仓库链接、评分、摘要、技术栈和风险。
- `⌘K` / `Ctrl+K` 能搜索并定位历史项目。
- 桌面和移动端不存在横向溢出，核心内容可正常阅读。
- 关闭 JavaScript 后，报告页面仍可访问。
- 生产构建成功，输出可直接部署到 Cloudflare Pages。
