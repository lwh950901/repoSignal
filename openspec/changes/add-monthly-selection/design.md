## Context

RepoSignal 是 Astro 静态站点，在构建阶段读取 `data/github-project-digest/daily/*.md` 与 `weekly/*.md`，将解析后的项目传给报告组件和浏览器本地搜索。现有 `DigestReport` 与 `ReportView` 围绕日报和周报的字段设计；月报需要 Top 5、角色推荐、观察信号和行动建议，继续向现有类型添加可选字段会显著增加分支和解析脆弱性。

本技术设计从 `docs/superpowers/specs/2026-07-20-monthly-selection-design.md` 转换而来；当 OpenSpec 工件之间出现歧义时，以该文件的产品目标、内容规则、页面结构和验收标准为范围基线。

开发必须保持静态发布、构建期无外部 API、禁用 JavaScript 后正文和主要导航可访问，并保护 main 工作区已有的日报与候选账本改动。实现位于隔离 worktree 的 `codex/monthly-selection` 分支。

## Goals / Non-Goals

**Goals:**

- 用固定 Markdown 字段定义并严格校验已发布月报。
- 为月报提供独立静态归档和已确认的档案式 UI。
- 在月、周、日之间切换时保留合理的时间上下文。
- 从仓库内数据确定性生成编辑候选初稿。
- 将月报加入现有本地搜索并优先展示月度记录。
- 用单元测试、类型检查、静态构建和响应式检查验证完整功能。

**Non-Goals:**

- 不自动决定 Top 5、角色、风险或趋势结论。
- 不在构建时访问 GitHub API，不增加数据库或客户端框架。
- 不公开完整候选池、综合评分算法、用户投票或评论。
- 不把日报和周报迁移到新的月报数据模型。

## Decisions

### 独立月报模型和视图

新增 `MonthlyReport`、`MonthlyProject`、`MonthlySignal` 与专属 Astro 组件；日报和周报继续使用 `DigestReport`。相较于把所有字段塞进一个联合对象，这能让必填字段、错误信息和 UI 边界保持清晰，也避免破坏现有报告。

### 固定 Markdown 字段而不是数据库或 JSON 内容文件

已发布内容位于 `data/github-project-digest/monthly/YYYY-MM.md`，解析器读取固定标题和中文字段。Markdown 保留编辑体验、版本历史和静态构建优势；严格校验弥补正则解析较脆弱的问题。JSON sidecar 会造成正文与结构化元数据双写，因此不采用。

Top 5 恰好五项；分类推荐以 8–12 项为编辑目标但不足时不补占位；观察信号以 2–4 条为目标；三类读者各提供 2–3 条行动建议。除 Top 5 和发布必填字段外，这些数量是内容验收目标，不用虚假数据换取固定数量。

### 初稿目录与发布目录隔离

生成器只写入被忽略的 `monthly-drafts/`，网站只 glob `monthly/`。人工审核后才把完整月报放入发布目录，避免未完成内容意外上线。生成器只聚合证据，不替代编辑判断。

### 时间锚点驱动周期切换

月报锚点为月末、周报锚点为 ISO 周末、日报锚点为当天。切换类型时选择不晚于锚点的最近报告；没有目标报告时进入该类型索引空状态。总是跳到最新一期实现更简单，但会让历史浏览失去上下文，因此不采用。

### 搜索类型由共享契约表达

把搜索项类型移动到 `search.ts`，增加 `monthly | weekly | daily`。匹配后按月、周、日排序，同类型内保持输入顺序。页面只显示类型徽标，报告标签仍用于可访问名称和检索。

### 服务端静态渲染优先

月报正文、周期导航、月份归档和仓库链接全部输出为普通 HTML 链接。JavaScript 只增强命令搜索和移动端选择器；`noscript` 提供月份链接。这样保持现有无 JavaScript 降级能力。

## Risks / Trade-offs

- [固定 Markdown 格式可能因编辑笔误构建失败] → 在发布前用解析器给出文件名、仓库和缺失字段，并在 CI 中运行测试和 Astro 构建。
- [候选数量和观察结论容易被误解为全行业统计] → 页面使用“RepoSignal 本月观察信号”，展示支撑项目和证据强度；不足三个项目时降级为编辑观察。
- [同一仓库同时出现在 Top 5 与分类推荐] → 以小写 `owner/repo` 全报告去重并阻止发布。
- [月报长页面在移动端信息过密] → Top 5 事实区、角色列和信号列在 768px 以下改为单列，360px 检查不得横向滚动。
- [相对 canonical URL 不如配置完整站点域名理想] → 第一版使用稳定路径 `/monthly/YYYY-MM/`；获得正式域名后可统一补充 Astro `site` 配置，不阻塞功能发布。
- [首期七月月报在自然月结束前发布] → 明确显示 `数据截止：2026-07-20`，后续判断在新月报或重新发布前由编辑审核。

## Migration Plan

1. 在不修改日报和周报数据格式的前提下新增解析器、生成器和纯周期映射。
2. 升级共享搜索契约与基础布局，迁移现有页面传入新 props。
3. 新增月报索引、历史路由和组件；无月报时先发布空状态。
4. 加入首期七月月报，运行完整测试、类型检查和生产构建。
5. 如需回滚，移除月报数据与路由，并把 `BaseLayout` 恢复为现有周报链接；日报和周报文件不需要迁移。

## Open Questions

当前实现范围内无未决问题。正式域名确定后再把相对 canonical 与 Open Graph URL 升级为绝对 URL。
