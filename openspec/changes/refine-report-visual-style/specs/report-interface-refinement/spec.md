## MODIFIED Requirements

### Requirement: 项目选择状态与评分必须语义分离
系统 SHALL 对有数字评分的项目显示数字及满分语境，并对无数字评分的周选项目显示明确的“周选”状态；系统 MUST NOT 使用看似数字评分的拆分英文占位符表达周选状态。共享项目条目 SHALL 在 0–100 范围内的有限数字评分旁显示十段静态辅助刻度，刻度 SHALL 与同一原始分数一致，不生成新的等级或推荐状态。

#### Scenario: 显示数字评分
- **WHEN** 项目记录包含数字评分
- **THEN** 项目条目显示该数字和 `/ 100` 满分语境
- **THEN** 评分为 0–100 范围内的有限值时显示十段辅助刻度

#### Scenario: 显示无评分周选状态
- **WHEN** 项目记录不包含数字评分
- **THEN** 项目条目显示紧凑的“周选”文本及对应无障碍名称
- **THEN** 项目条目不显示 `W` 与 `EEKLY` 拼接占位符
- **THEN** 项目条目不显示评分刻度

#### Scenario: 刻度保留分数精度
- **WHEN** 共享项目条目的评分为 86
- **THEN** 十段刻度中的前八段完全填充，第九段填充 60%，第十段不填充
- **THEN** 可见评分仍为 `86 / 100`，不四舍五入为新的评分或等级

#### Scenario: 正确表示零分与满分
- **WHEN** 共享项目条目的评分分别为 0 或 100
- **THEN** 0 分条目显示 `0 / 100` 和十段未填充刻度，不显示“周选”
- **THEN** 100 分条目显示 `100 / 100` 和十段完全填充刻度

#### Scenario: 非有效范围输入不生成误导刻度
- **WHEN** 评分输入超出 0–100 范围或不是有限值
- **THEN** 项目条目不生成辅助刻度
- **THEN** 系统不通过截断、替换或重新计算来制造有效评分，也不修改原始报告数据

#### Scenario: 辅助刻度不增加交互或重复播报
- **WHEN** 读者使用键盘或辅助技术访问有评分项目
- **THEN** 数字评分及满分语境仍可被读取
- **THEN** 辅助刻度对辅助技术隐藏，不能获得键盘焦点，也不表达任务进度

#### Scenario: 刻度在静态页面与生产安全策略下可用
- **WHEN** 页面采用现有生产 CSP 加载且 JavaScript 被禁用
- **THEN** 有效评分的数字和静态刻度仍完整显示
- **THEN** 刻度不依赖行内样式、行内脚本、渐变或运行时动画，不要求放宽 CSP

### Requirement: 间距与视觉身份必须保持一致层级
系统 SHALL 使用严格递增的中高层级间距令牌区分组件内部、组件之间和章节之间的留白。精修后的界面 MUST 保留既有纸张色、苔绿色、标记黄色、细分隔线、直角边界和克制动效。系统 SHALL 在日报、周报、月报、每日可行性方案、开源雷达周刊及共享搜索界面中使用一致的基础视觉规则，并为重点色提供明确语义。

#### Scenario: 中高层级间距递进
- **WHEN** 全局样式令牌被加载
- **THEN** `--space-5`、`--space-6`、`--space-7` 与 `--space-8` 的值严格递增

#### Scenario: 保留既有视觉身份
- **WHEN** 日报、周报、月报、每日可行性方案或开源雷达周刊被渲染
- **THEN** 页面继续使用既有核心色板、直角边界和档案式分隔结构
- **THEN** 页面不因本次精修引入渐变卡片、装饰阴影或持续动画

#### Scenario: 普通分类与重点标记语义分离
- **WHEN** 普通项目分类、简介与展开分析被渲染
- **THEN** 普通分类标签使用浅底或文字样式且不旋转，简介和展开分析使用普通边界色
- **THEN** 黄色强调只用于当前选择或由已有数据明确标注的重点，例如月报“本月核心”
- **THEN** 高分本身不产生新的重点身份，评分刻度使用苔绿色

## ADDED Requirements

### Requirement: 报告与共享控件必须使用可读字号和明确字体角色
系统 SHALL 在默认根字号 15px、浏览器缩放 100% 时，为辅助信息提供至少 12px 的字号，为中文导航、字段名、按钮文字和展开入口提供约 13px 的字号，为叙述性正文与事实描述提供 15–16px 的字号。系统 SHALL 将中文标题、正文和控件分配到现有正文无衬线字体栈，将仓库名、日期、评分和技术标识分配到现有等宽字体栈，并保留系统字体回退。

#### Scenario: 五类报告使用相同文字尺度
- **WHEN** 日报、周报、月报、每日可行性方案或开源雷达周刊在默认缩放下显示
- **THEN** 说明、分类标签、日期、表头与评分分母不小于 12px
- **THEN** 中文导航、字段名、按钮文字和展开入口约为 13px，正文和叙述性事实描述为 15–16px
- **THEN** 正文行高为字号的 1.75–1.85 倍，标题保留独立层级

#### Scenario: 搜索界面的辅助信息可读
- **WHEN** 搜索面板显示结果、类型标记、元信息或空状态
- **THEN** 辅助信息不小于 12px，搜索输入和叙述性空状态文字为 15–16px
- **THEN** 选中结果与键盘焦点仍清晰可辨

#### Scenario: 中文与技术内容使用不同字体角色
- **WHEN** 页面同时显示中文控件、仓库名、日期与评分
- **THEN** 中文控件使用正文无衬线字体栈且不采用英文眉题式大字距
- **THEN** 仓库名、日期与评分使用等宽字体栈

#### Scenario: 字体服务不可用
- **WHEN** 外部字体加载失败
- **THEN** 页面通过既有系统字体回退继续显示所有文字
- **THEN** 导航、长仓库名与评分不因字体回退而重叠或越出页面边界

### Requirement: 项目内容必须通过留白与字重呈现层级
系统 SHALL 保留共享项目条目的语义化字段结构和内容顺序，通过内部间距、推荐内容字重和项目间分隔组织信息。系统 MUST NOT 为每个事实字段重复绘制上边框，也 MUST NOT 因减少边界而隐藏风险或推荐内容。

#### Scenario: 阅读包含全部字段的项目
- **WHEN** 项目同时包含定位、简介、技术栈、风险、推荐依据和完整分析
- **THEN** 内容保持“定位、简介、事实字段、完整分析”的顺序，事实字段保持既有相对顺序
- **THEN** 简介保持独立轻量样式，不成为嵌套卡片
- **THEN** 项目字段以 12–15px 量级的间距分组，推荐内容使用 500 字重，风险保持明确标签
- **THEN** 相邻项目之间保留细分隔线，每个项目使用约 30px 的上下内边距

#### Scenario: 部分字段缺失
- **WHEN** 项目缺少技术栈、风险或推荐依据中的部分字段
- **THEN** 剩余字段仍获得与自身语义对应的样式
- **THEN** 不出现空字段占位，推荐强调不因字段位置变化而落到其他内容上

#### Scenario: 阅读表格与事实矩阵
- **WHEN** 月报事实矩阵、报告表格或章节边界显示
- **THEN** 必要的行列分隔和章节边界继续保留，项目字段去边框规则不影响这些结构

### Requirement: 长文行长必须受控且不压缩数据区域
系统 SHALL 对报告中的定位、简介、长事实描述及分析段落和列表设置 42–46em 范围内的最大阅读宽度，默认采用 44em，并服从可用容器宽度。系统 MUST NOT 将该限制施加到所有 `.prose` 容器、表格、评分面板或封面上。

#### Scenario: 宽屏阅读长段落
- **WHEN** 报告内容区域宽于设定的最大阅读宽度
- **THEN** 长段落和列表在该最大宽度处换行
- **THEN** 表格、评分面板与封面仍可使用自身布局允许的宽度

#### Scenario: 收起归档栏
- **WHEN** 读者收起桌面归档栏，报告可用宽度增大
- **THEN** 长段落继续受相同最大阅读宽度约束
- **THEN** 评分与宽内容区域正常利用增加的空间

#### Scenario: 窄屏显示长仓库名与数据
- **WHEN** 320px 或 390px 宽视口显示长仓库名、长链接、长段落和报告表格
- **THEN** 长文本可换行，标题与评分不互相遮挡，不通过缩小正文或辅助信息字号解决溢出
- **THEN** 表格使用既有局部滚动或移动端字段布局，整个页面不出现横向滚动

### Requirement: 归档当前项必须具有持久且多重的识别方式
系统 SHALL 基于已有 `aria-current="page"` 状态显示当前归档项，使用整行浅色背景、左侧短竖条和较强字重共同表达选择。系统 SHALL 保留时间线、日期节点及“最新”标签的既有含义，避免将当前项等同于最新项。

#### Scenario: 当前报告不是最新报告
- **WHEN** 读者访问一篇历史报告
- **THEN** 只有匹配当前报告的归档项具有当前选择样式和 `aria-current="page"`
- **THEN** “最新”标签仍位于最新报告旁，不随当前选择移动

#### Scenario: 指针悬停或键盘访问归档
- **WHEN** 读者悬停普通归档项或使用键盘聚焦任一归档链接
- **THEN** 悬停背景与键盘焦点轮廓可被识别，当前选择样式保持可辨
- **THEN** 行中文字不因状态变化而跳动，焦点轮廓不被轨道滚动容器裁切

#### Scenario: 归档收起或切换移动端
- **WHEN** 桌面归档被收起，或页面进入移动端布局
- **THEN** 收起状态保留可操作且有清晰焦点的展开按钮，不新增缩略时间线
- **THEN** 移动端原生报告选择器显示当前报告并保留既有切换行为

### Requirement: 样式优化必须保留响应式与渐进增强体验
系统 SHALL 在五类报告及共享搜索界面中保留原有导航、搜索、原生详情、日期切换和静态阅读能力。系统 SHALL 在默认缩放下的 1440px、1024px、768px、390px、320px 视口中维持可读文字和无重叠布局，并兼容 200% 缩放及减少动态效果偏好。

#### Scenario: 导航宽度不足
- **WHEN** 五个周期导航标签宽于当前可用空间
- **THEN** 导航可以进入现有两行页头模式并在独立一行横向滚动
- **THEN** 标签保持现有顺序、可点击和可聚焦，不与品牌或搜索按钮重叠
- **THEN** 页面整体不因导航而横向溢出

#### Scenario: 键盘操作与页面缩放
- **WHEN** 读者在 200% 缩放下使用键盘访问导航、搜索、归档与详情控件
- **THEN** 各控件保持可见、可操作并有清晰焦点轮廓
- **THEN** 正文、控件与评分不重叠，必要的内容可通过正常滚动访问
- **THEN** 搜索结果选择状态与详情默认展开状态保持现有行为

#### Scenario: 禁用 JavaScript 阅读
- **WHEN** 读者禁用 JavaScript 后访问任一报告
- **THEN** 报告正文、周期导航、归档备用链接及 GitHub 链接继续可读可访问
- **THEN** 原生详情仍可展开，新评分刻度不依赖客户端脚本
- **THEN** 不将原有依赖 JavaScript 的搜索弹窗或 select 自动跳转作为无脚本要求

#### Scenario: 减少动态效果
- **WHEN** 读者启用减少动态效果偏好
- **THEN** 页面继续遵循现有减少动态效果规则
- **THEN** 评分刻度保持静态，本次优化不引入持续动画或新的加载动效
