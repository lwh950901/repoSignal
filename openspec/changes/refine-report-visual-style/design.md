## Context

RepoSignal 是面向开发者的开源项目研究档案。页面的首要任务是帮助读者识别项目用途、推荐依据和风险，再按需阅读详细分析。样式优化沿用 proposal.md 的完整范围，覆盖五类报告及共享归档、导航、搜索界面。

当前实现采用 Astro 静态输出与集中式 `src/styles/global.css`。根字号为 15px，辅助文本大量使用 0.66–0.75rem；项目字段逐行带边框，部分长段落最大宽度为 62rem。`ArchiveTimeline.astro` 已提供 `.active` 和 `aria-current="page"`，日期轨道无需新增状态或脚本。`ProjectEntry.astro` 统一渲染日报、周报及其他页面复用的项目条目。

现有规格要求保留纸张色、苔绿、标记黄、直角边界、档案式分隔结构、原生渐进披露和克制动效。生产 CSP 限制行内样式和脚本，因此新视觉元素应随静态 HTML/CSS 输出。现有布局测试包含具体 CSS 宽度断言，需要区分行为契约与将被本次优化替换的样式数值。

## Goals / Non-Goals

**Goals:**

- 提升中文辅助信息的可读性，并用字体角色建立稳定层级。
- 通过间距、边界与字重，使项目身份、推荐理由、风险和技术信息容易区分。
- 让当前归档日期在指针、键盘和移动端访问中都容易识别。
- 控制长段落行长，同时保留表格、评分和封面的布局空间。
- 用真实分数驱动的简短刻度形成 RepoSignal 的视觉记忆点。
- 保证五类报告、搜索、窄屏、归档收起及无 JavaScript 阅读体验一致。

**Non-Goals:**

- 不改变报告内容、评分算法、数据解析、路由或周期导航的时间锚点逻辑。
- 不新增筛选、排序、评分等级或新的推荐状态。
- 不重做首页信息架构，不改变日报隐藏标题及现有详情默认展开状态。
- 不引入新字体请求、UI 库、动画库或运行时服务。

## Decisions

### 1. 沿用档案布局，在现有组件内精修

选择“档案式阅读工作台”：左侧时间索引与右侧项目纵向列表保持原位。视觉重点只放在项目身份、当前选择和真实评分上。

比较过两种替代方向：全卡片布局会增加容器边界与滚动高度；压缩为表格会削弱长段落和风险分析的可读性。现有档案结构更符合连续阅读与历史查阅任务。

桌面概念：

```text
RepoSignal             五类报告导航                  搜索
────────────────────────────────────────────────────────
归档日期         报告标题 / 现有摘要（有则显示）
  历史日期       ────────────────────────────────────────
▌ 当前日期       分类标签       owner/repository     86/100
  历史日期                                          ▰▰▰▰▱
                 项目定位
                 简介

                 技术栈        标签  标签
                 观察风险      风险内容
                 为什么推荐    推荐依据
                 + 查看完整分析
                 ────────────────────────────────────────
```

图中的刻度为位置示意，实际为十段。移动端继续使用品牌与搜索一行、可横向滚动的周期导航一行，随后是原生报告选择器和单列正文。

自检：保留“时间索引 + 项目分析”的业务结构；不新增装饰编号、大数字摘要或仪表盘模块。刻度直接编码评分，是本次唯一新增的识别元素。

### 2. 用现有色板建立语义，而非增加颜色

| 角色 | 色值 | 使用范围 |
| --- | --- | --- |
| 纸张底色 | `#F3F5F2` | 页面背景 |
| 阅读面 | `#FBFCFA` | 展开内容、搜索等局部阅读区域 |
| 主文字 | `#17201B` | 标题、正文、关键数字 |
| 次文字 | `#526059` | 辅助说明与字段名 |
| 交互绿 | `#56705E` | 链接、当前项竖条、评分填充 |
| 标记黄 | `#E4C95A` | 当前日期节点、已有明确核心标记 |

继续复用 `--paper-deep` 作为浅底、`--rule` 作为边线、`--danger` 作为已有风险语义色。普通分类标签不使用黄底或倾斜；简介和展开分析的边线改用普通分隔色。月报已有“本月核心”标记仍可使用黄色。

键盘焦点采用深色或苔绿的清晰轮廓，避免浅底上仅靠黄色轮廓识别。评分条使用苔绿，不能因高分自动获得黄色“重点”身份。

替代方案是重新换色或按类别分配鲜艳颜色，但这会扩大视觉变化并让分类争夺注意力。优先收敛现有色板的职责。

### 3. 明确字体角色与字号尺度

保留现有字体加载和回退链。仓库标题作为有辨识度的展示文字，使用 IBM Plex Mono；中文报告标题与正文使用 Noto Sans SC，并回退 PingFang SC、Microsoft YaHei；日期、分数及技术标识使用等宽字体。中文导航、按钮、字段名和说明不再统一继承等宽字体。

保持根字号 15px，避免通过全局放大改变所有 rem 布局尺寸。增加共享字号令牌并替换相关组件声明：

| 层级 | 目标 | 用途 |
| --- | --- | --- |
| 辅助 | 0.8rem / 12px | 标签、日期、表头、快捷键、评分分母 |
| 控件 | 0.8667rem / 约 13px | 导航、字段名、按钮、展开入口 |
| 正文 | 1rem / 15px | 分析、事实值、搜索输入；重点摘要可到 16px |
| 项目标题 | 约 20–28px，响应式 | 仓库名，字重 500 |
| 报告标题 | 沿用响应式范围 | 中文主标题，字重 600 |

正文行高约 1.75，长文可到 1.85；中文标签不使用英文眉题式大字距。中文标题沿用正文家族，避免为追求额外展示字体引入下载与回退不一致。

五类报告中的说明、表头、评分标签，以及搜索元信息和结果类型标记都应用同一尺度。正文父级应达到目标字号，不能只放大局部标签。

### 4. 保留外部分隔，内部通过间距建立层级

保持 `--space-5` 到 `--space-8` 严格递增及当前数值。项目内部以 12–15px 的间距组织字段，项目外部垂直留白使用约 30px，章节使用约 45px。

`project-facts` 保留语义化 `dl` 与桌面标签列；去掉字段逐行上边框，以间距区分技术栈、风险和推荐依据。推荐内容使用 500 字重，风险仍有明确文字标签。必要时增加字段专用 class，避免依赖 `nth-child`，因为字段可缺省。

保留“定位 → 简介 → 事实 → 完整分析”的顺序。简介保持独立样式、较弱颜色与轻量左边界，不包成嵌套卡片；普通分类标签去掉旋转和强对比大色块。表格、月报事实矩阵及章节边界仍可保留必要横线。

替代方案是删除所有边线，但会破坏档案结构与表格行列辨识；本方案只减少造成重复层级的边界。

### 5. 对段落限制宽度，对结构保留空间

为长文建立以 44em 为默认值的阅读宽度，实际落在 42–46em 目标范围。约束定位、简介、长事实值以及分析区域中的段落和列表，使用 `max-width` 并服从父容器可用宽度。

不对全局 `.prose` 容器统一缩窄，也不全局修改所有 `p`：雷达正文的外层、月报机会表格、可行性评分和封面保留既有可用宽度。使用限定到报告区域的选择器，必要时为长文本字段增加 class。

长仓库名与链接允许换行；标题列设 `min-width: 0`，评分区保持紧凑。小屏不通过缩小字体来避免溢出，必要时让项目标题与评分换行排列。表格保持已有局部横向滚动或移动端字段布局，不产生整个页面的横向滚动。

替代方案是缩窄整个内容栏，但会同时压缩数据区。段落级限制也能避免归档栏收起后行长无限增长。

### 6. 基于已有归档状态绘制当前项

复用 `ArchiveTimeline.astro` 的 `aria-current="page"` 作为当前项选择器；保留时间线、小圆点及“最新”标签的现有含义。当前项使用浅绿整行底、左侧短竖条和较强字重，节点可以使用黄色。

普通行预留相同的边界或内边距，防止切换时文字跳动。hover 仅提供轻背景反馈；focus-visible 使用独立轮廓，当前态在两者叠加时仍可识别。轨道内部留足焦点轮廓空间，避免滚动容器裁切。

桌面折叠仅调整既有折叠按钮的可见焦点与文字大小，不新增缩略时间线。移动端仍由原生 select 的 selected 值表示当前报告，禁用 JavaScript 时继续显示现有归档链接。

替代方案是由 JavaScript 维护额外高亮状态，容易与路由不一致；静态状态已足够。

### 7. 静态 SVG 表达评分，不增加交互

仅在 `ProjectEntry.astro` 中已有有效数字评分的位置增加十段小刻度，宽约 58px、高约 6px，置于数字下方。保留分数、`/ 100` 和评分的可访问文本；SVG 使用 `aria-hidden="true"` 与 `focusable="false"`，不重复播报、不增加 Tab 停靠点。

每段表示 10 分，内部填充比例为 `clamp(score - 段索引 × 10, 0, 10) / 10`。例如 86 分显示八段满、一段 60%、最后一段空；0 分仍是有效数字评分，显示空刻度而不是“周选”；100 分为十段满。使用显式数字存在性与有限值判断，避免现有 truthy 分支将零分误当成缺失。

有效范围为 0–100。超范围或非有限值不生成刻度、不自动修正原始数据；实施时确认解析器契约并覆盖边界输入。缺失评分的项目继续使用既有“周选”语义与无障碍名称。

Astro 构建时计算每个 SVG rect 的 `x` 和 `width` 属性，颜色由外部 CSS class 设置。无需行内 style、动态 CSS 变量、渐变或客户端 JS，因此不放宽 CSP。月报和可行性方案已有评分面板保留表达形式，只统一基础字体与配色。

替代方案：整段四舍五入会降低表达精度；CSS 动态宽度需要额外处理 CSP；动画进度条会把静态评价误读成任务进度。静态分段 SVG 能保留精度且实现局部化。

### 8. 在原样式区段修改，验证行为与视觉两个层面

集中修改已有选择器及令牌，不在文件底部追加一套覆盖层，不引入 `!important`。检查移动端 media query 和类似 `.project-score span` 的宽泛规则，避免覆盖新刻度或字号。只在字段语义或 SVG 输出需要时调整 Astro 标记。

验证分为以下两层：

- 契约检查：保留导航、静态阅读、搜索名称、归档复用、月报原生详情等现有检查。更新被本次阅读宽度调整取代的具体数值断言；新增对有评分、缺失评分、0、86、100 等输出的必要检查，确认刻度与数字一致且对辅助技术隐藏。优先验证实际渲染输出，不用仅包含 CSS 字符串来证明视觉效果。
- 浏览器检查：五类报告和搜索在 1440px、1024px、768px、390px、320px 下检查字号、换行和页面溢出；桌面检查归档展开与收起、长仓库名及长正文。检查当前归档、hover、键盘焦点、详情展开、搜索选中结果和移动端选择器，并覆盖 200% 缩放、减少动态效果及禁用 JavaScript 的阅读路径。使用实际报告内容，记录代表性截图。

实施阶段运行定向布局测试、`npm run check` 和 `npm run build`，浏览器以实际运行或构建后的页面为准。此前预览未成功启动，因此截图验证是待执行工作，不能将代码审阅当作视觉验收。

## Risks / Trade-offs

- 字号放大可能挤压五项导航和日期轨道 → 检查中等宽度；保留移动端单行横向滚动导航，必要时让两行页头更早生效，不把标签缩回小字。
- 减少横线可能削弱字段归属 → 保留固定标签列、字段间距和项目外部分隔，使用真实长内容检查。
- 全局 CSS 影响五类页面 → 通过共享令牌统一基础样式，按组件限定阅读宽度和边框变更，逐类查看代表页面。
- 当前项浅底不能单独表达选择 → 同时使用短竖条、字重与 `aria-current`，检查焦点轮廓与文字对比。
- 外部字体加载失败会改变换行 → 保留系统字体回退，并在字体不可用时检查长仓库名和导航。
- 现有测试锁定旧宽度可能出现预期失败 → 只更新与本次设计明确对应的断言，保留其余行为契约，不以删除测试换取通过。
- 新刻度可能看起来像评分等级或进度 → 保持静态、单色、小尺寸，并始终紧邻真实数字，不添加等级名称。

## Migration Plan

1. 完成该变更的规格和任务文档后实施。先更新基础字号、间距与颜色语义，再调整段落宽度、归档状态和项目评分输出。
2. 使用项目现有构建流程验证并生成静态站点，完成上述浏览器检查后交付。无需数据迁移或新增部署配置。
3. 若出现回归，回退本次样式与组件改动即可；不回退报告数据、既有业务逻辑或其他未关联工作。
