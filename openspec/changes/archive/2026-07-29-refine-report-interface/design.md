## Context

RepoSignal 是 Astro 构建的静态报告档案。界面以纸张底色、等宽数据字体、细分隔线和左侧归档轨为主要语言，日报与周报共用 `ProjectEntry`，月报使用独立的研究视图。当前实现没有客户端框架或设计系统依赖，样式集中在 `global.css`，布局契约由源文件级测试保护。

本次变更横跨共享页头、项目条目、月报结构和全局间距，因此需要在保持静态 HTML、无 JavaScript可读和现有视觉身份的约束下统一设计。

## Goals / Non-Goals

**Goals:**

- 让数字评分与“周选”状态在视觉和语义上明确区分。
- 让窄屏用户无需理解键盘快捷键也能识别搜索入口。
- 让月报读者能快速跳到主要章节，并按需展开项目的评分与核实证据。
- 让间距令牌形成真实递进关系，为标题、组件和章节提供稳定节奏。
- 保持键盘焦点、减少动态偏好、移动端无横向溢出和无 JavaScript 阅读能力。

**Non-Goals:**

- 不改变报告 Markdown 契约、解析器、搜索索引或路由。
- 不新增字体、图标库、客户端框架或外部依赖。
- 不更换既有色板，不引入圆角卡片、渐变、阴影或持续动画。
- 不重新设计日报、周报和月报的信息架构。

## Decisions

### 1. 将项目右侧状态拆成两种明确呈现

有数字评分时继续显示大号分数与 `/100`；没有数字评分时显示紧凑的“周选”文字徽记，并使用独立的无障碍名称。不会以 `W` 和 `EEKLY` 拼接状态，因为它借用了数字评分的视觉位置和层级，容易被误读为缺失或异常分数。

备选方案是完全隐藏无评分区域。未采用，因为条目右侧仍需要一个与数字评分等价的选择状态，且“周选”能解释该项目为何出现在报告中。

### 2. 使用内联 SVG 作为搜索入口的持久识别符

在搜索按钮内加入简单的放大镜 SVG。桌面端保留“搜索”和快捷键；移动端隐藏文字与快捷键，仅保留具有足够点击面积的图标和现有 `aria-label`。

备选方案是使用 Unicode 字符。未采用，因为不同平台字形和基线不稳定。也不引入图标库，避免为单个图标增加依赖。

### 3. 月报采用“章节导航 + 原生 details 渐进披露”

在月报摘要后加入三个页内链接：Top 5、业务机会、研究说明。为研究说明补充稳定 `id`。

每个 Top 5 项目的仓库名、定位、总分和“本月变化”保持始终可见；事实表、六维评分、分析判断和来源放入原生 `<details>`，摘要为“查看评分与核实证据”。原生元素在无 JavaScript环境中仍可操作，键盘和辅助技术语义也优于自定义折叠组件。

备选方案包括吸顶目录和客户端手风琴。吸顶目录会与现有归档轨争夺视觉注意力，客户端手风琴增加状态逻辑且破坏渐进增强，因此不采用。

### 4. 间距令牌采用有限的递进尺度

保留 `--space-1` 至 `--space-8` 的命名以降低迁移风险，将中高层级调整为 `1.25rem`、`1.5rem`、`2rem`、`3rem`。组件内部使用 5–6，章节与页面分隔使用 7–8。只调整现有令牌值和本次新增组件，不进行无关的选择器重写。

备选方案是删除重复令牌并重新命名为语义变量。未采用，因为现有样式引用广泛，本次目标是恢复层级而不是重建完整设计系统。

### 5. 用契约测试和真实视口共同验证

先扩展 `layout-contract.test.ts`，使其对周选文本、搜索 SVG、月报导航、原生折叠和递进间距产生失败，再实施最小代码变更。完成后运行单测、Astro 类型检查和生产构建，并在桌面与 390px 移动视口检查月报、周报和搜索面板。

## Risks / Trade-offs

- [折叠证据降低默认可见性] → 保留项目判断与本月变化在折叠外，摘要明确说明其中包含“评分与核实证据”，所有内容仍存在于静态 HTML。
- [新的间距尺度可能改变多个页面高度] → 通过桌面和移动视口逐页检查，重点确认页头、归档轨、项目间距和月报章节。
- [图标按钮在移动端可能缺少文字提示] → 保留明确的 `aria-label`、可见放大镜和至少 2.75rem 的触控面积。
- [页内链接可能被章节边缘截断] → 继续使用章节 `scroll-margin-top`，并为研究说明提供稳定锚点。
