## Context

站点当前在构建阶段从 `monthly/`、`weekly/` 和 `daily/` 三个冻结 Markdown 目录发现内容，通过 Astro 静态路由生成页面。共享 `PeriodSwitcher` 只支持月、周、日三种报告类型；周报和日报使用 `DateRail`，月报使用自己的侧栏外壳，但三者都复用 `ArchiveTimeline` 的日期时间线。

开源雷达周刊已经有一篇审核中的公众号稿和固定封面，但稿件位于不参与构建的 `distribution-drafts/`，其中还包含传播用 UTM 与站点域名占位符。新页面必须保持公开冻结内容与内部传播草稿分离，并继续满足纯静态构建、无 JavaScript 可读和现有视觉身份约束。

## Goals / Non-Goals

**Goals:**

- 从独立公开目录发现审核后的雷达周刊，并为每期生成稳定静态 URL。
- 在所有报告页顶部提供完整的“开源雷达周刊”Tab，并链接到最新一期或安全的归档入口。
- 为雷达周刊提供与现有报告一致的左侧时间线、当前项、最新标记、折叠行为和移动端选择器。
- 以文章阅读为中心展示固定封面、标题、分组正文、项目链接、风险和试用建议。
- 首期发布 `2026-W31`，并使用相对站内链接消除草稿中的域名占位符。
- 通过解析、导航、布局契约和生产构建验证新内容类型。

**Non-Goals:**

- 不自动将 `distribution-drafts/` 中的草稿发布到公开目录。
- 不接入公众号发布 API、订阅系统、数据库或服务端运行时。
- 不把雷达周刊的重复项目条目加入现有项目搜索索引。
- 不改变日报、研究周报或月报的内容格式与排序。
- 不在本次变更中实现站点域名、分析平台或 UTM 数据回收。

## Decisions

### 1. 使用独立冻结目录和独立内容模型

公开文章存放在 `data/github-project-digest/radar/YYYY-Www.md`，文件名是路由与归档排序的唯一周期标识。新增 `src/lib/radar.ts`，定义独立的 `RadarReport`，至少包含 `slug`、`title`、`description`、`cover`、`markdown` 和 `html`。

加载器从首个一级标题读取标题，从首张 Markdown 图片读取封面与替代文本，并将标题和封面从正文 Markdown 中移除后再交给 `marked`。首个普通段落作为页面 description。文件名必须符合 ISO 周格式，且标题和封面缺失时构建应明确失败。

选择独立模型而不是扩展 `DigestReport`，因为雷达周刊是连续文章，不包含日报/周报所需的结构化评分、项目类型和额外发现。直接读取 `distribution-drafts/` 虽然更省文件，但会破坏草稿与公开结论的边界，并可能发布占位符。

### 2. 新增独立静态路由，Tab 直接进入最新一期

新增：

- `/radar/[week]/`：通过 `getStaticPaths()` 为每个冻结 Markdown 生成单期文章。
- `/radar/`：在没有具体周期上下文时提供归档入口，并链接到最新一期。

`ReportPeriod` 扩展为 `"monthly" | "weekly" | "daily" | "radar"`。`resolvePeriodLinks` 接收雷达周刊 slug 列表，返回四个最新入口；任一类型没有内容时回退到对应 index。顶部 Tab 的显示文案使用完整的“开源雷达周刊”，而路径保持简短的 `/radar/`。

不让 `/radar/` 在运行时重定向，因为站点是纯静态输出；与现有周报、日报 index 一样提供可读链接即可。常规页面上的 Tab 会直接指向最新 `/radar/YYYY-Www/`，减少一次点击。

### 3. 复用时间线，扩展现有 DateRail 的结构类型

`DateRail` 不再只接收 `DigestReport[]`，而是接收具备 `slug` 与 `date` 的最小归档记录，并支持 `weekly`、`daily`、`radar` 三种 period。雷达模式使用：

- 眉题：`RADAR`
- 无障碍归档名称：`开源雷达周刊`
- 时间线标签：ISO 周 slug，例如 `2026-W31`
- 路径：`/radar/YYYY-Www/`
- 移动选择器：`YYYY-Www 开源雷达周刊`

该组件继续只负责数据到归档项的适配，圆点、当前项和“最新”标记仍由 `ArchiveTimeline` 统一渲染。相比复制一个雷达专用侧栏，这样可以让折叠、无脚本链接和移动选择器维持同一行为。

### 4. 使用专用文章视图，不复用项目卡片视图

新增 `RadarReportView.astro`，结构为现有 `archive-shell` 加 `DateRail`，右侧使用 `article.radar-article`：

1. 封面图片；
2. 周刊标题和 ISO 周标识；
3. 经 `marked` 渲染的正文；
4. 原生项目链接和站内周报链接。

不复用 `ReportView` 或 `ProjectEntry`，因为雷达文章的段落顺序和编辑语气是公开内容的一部分，重新解析为项目卡片会丢失文章结构。样式复用现有纸张色、苔绿色、黄色标记、细分隔线和 `.prose` 排版，只新增封面宽高比、正文阅读宽度和章节间距。

### 5. 顶部导航在移动端采用两行布局

加入完整的“开源雷达周刊”后，现有单行三列页头在窄屏上会挤压品牌和搜索入口。桌面端继续使用品牌／周期导航／操作区三列；不大于 768px 时将周期导航放到第二行并横向居中，品牌与搜索保留在第一行。Tab 保持完整文案和至少 2.75rem 的触控高度，不用只在视觉上缩写为“雷达”。

相比在移动端缩短标签，两行布局能保持用户要求的完整名称和无障碍一致性；代价是页头高度增加一行，但不会影响静态内容或归档布局。

### 6. 首期文章从批准稿手动冻结

首期以 `distribution-drafts/2026-W31-wechat.md` 当前批准稿为来源，复制到 `radar/2026-W31.md` 后做两项公开化调整：

- 封面路径改为 `/covers/repository-radar-weekly-subtitle.png`；
- `{{SITE_BASE_URL}}` 的阅读全文链接改为站内相对链接 `/weekly/2026-W31/`，不携带草稿 UTM。

后续每期仍由编辑明确复制并审核，构建过程不自动同步草稿。这样发布动作是可审查的 Git 变更，回滚也只需撤销对应冻结文件。

### 7. 雷达文章暂不进入项目搜索索引

雷达文章介绍的项目与同周研究周报高度重叠。首版只让页面可通过顶部 Tab、归档时间线和静态 URL 访问，不为每个项目创建新的搜索条目，避免搜索结果出现内容几乎相同的双份记录。

如果后续需要搜索雷达文章，应新增文章级结果类型，而不是复制项目级索引；该能力留到独立变更处理。

## Risks / Trade-offs

- [公开文章与内部草稿形成两份内容，后续可能漂移] → 公开目录只接受人工冻结版本；发布检查验证封面、站内链接和占位符，冻结后不自动回写草稿。
- [完整 Tab 导致移动端页头过高或拥挤] → 使用两行响应式布局并增加布局契约测试，验证完整标签和触控高度。
- [扩展共享周期类型会影响所有页面的 TypeScript 调用点] → 先增加失败测试，再一次性更新 `resolvePeriodLinks`、`BaseLayout`、各页面和 index 的四类型契约。
- [Markdown 图片或标题格式错误导致页面缺少关键内容] → `radar.ts` 对 ISO 周文件名、一级标题和首张封面执行构建期校验，并在测试中覆盖错误输入。
- [文章中的外部项目事实会随时间变化] → 页面呈现冻结文章，不在构建时访问 GitHub；后续修订通过新的内容提交完成。
- [雷达文章与研究周报内容重复] → 保持不同 URL 和内容定位，首版不加入项目搜索索引，并从雷达正文明确链接到完整研究周报。

## Migration Plan

1. 增加雷达内容解析器及失败测试，冻结首期公开 Markdown 和封面路径。
2. 扩展周期类型、最新链接解析和共享顶部 Tab，补齐所有现有页面的雷达入口。
3. 扩展 `DateRail` 并新增雷达文章视图、单期路由和 index。
4. 添加响应式样式、布局契约和无脚本可读性验证。
5. 运行定向测试、全量测试、Astro check 和生产构建，并在桌面与移动宽度检查页面。

回滚时删除雷达路由、加载器和公开目录，恢复三类型周期导航及移动页头样式；原月报、周报和日报数据不需要迁移。
